# C42. 文件读写

## 节点定位

- 所属模块：文件、调试与综合应用
- 学习难度：综合应用
- 建议学习时间：120-150 分钟
- 典型用途：从文件读取已有数据，或把程序结果保存下来供以后继续使用。

## 学习目标

- 理解文件、文件流和 `FILE *` 的基本关系。
- 掌握常见打开模式，并理解覆盖、追加和读写位置的差异。
- 会使用字符、行和格式化函数读写文本文件。
- 会根据返回值区分读取成功、到达文件末尾和发生错误。
- 会使用 `fread`、`fwrite` 完成基本二进制读写。
- 能正确处理打开失败、提前返回和关闭失败。
- 理解相对路径、当前工作目录及文本格式设计的重要性。

## 一、为什么需要文件

普通变量、数组和动态内存中的数据只在程序运行期间存在。程序结束后，这些运行时数据通常随进程一起消失。

文件能够把数据保存在外部存储设备中。例如，成绩管理程序可以把学生记录保存到 `students.txt`，下次运行时再读取，而不必重新输入。

文件操作通常包含以下步骤：

```text
确定路径与模式 -> 打开文件 -> 检查是否成功 -> 读写数据 -> 检查结果 -> 关闭文件
```

其中任何一步都可能失败，因此文件操作不能只写“正常情况”。

## 二、什么是文件流与 FILE 指针

标准库把文件以及标准输入输出都抽象为流。流可以理解为程序与外部数据来源或去向之间的通道。

打开文件后，`fopen` 返回 `FILE *`：

```c
FILE *file = fopen("data.txt", "r");
```

`FILE` 是 `<stdio.h>` 中定义的类型，标准库使用它记录文件状态、当前位置、缓冲区和错误信息。程序不应直接访问 `FILE` 内部成员，只通过标准文件函数操作它。

`FILE *` 常称为文件指针。它不是文件内容本身，而是标准库用于代表一个已打开文件流的指针。

## 三、打开文件并检查结果

```c
#include <stdio.h>

int main(void) {
    FILE *file = fopen("data.txt", "r");

    if (file == NULL) {
        printf("无法打开文件\n");
        return 1;
    }

    fclose(file);
    return 0;
}
```

`fopen` 失败时返回 `NULL`。可能原因包括：

- 读取模式下文件不存在；
- 路径中的目录不存在；
- 当前用户没有权限；
- 文件被系统或其他程序以不兼容方式占用；
- 系统资源不足；
- 路径格式不符合当前运行环境要求。

在检查成功之前，不能把返回值交给其他文件读写函数。

## 四、常见打开模式

| 模式 | 文件必须已存在 | 原内容 | 初始位置 | 主要用途 |
| --- | --- | --- | --- | --- |
| `"r"` | 是 | 保留 | 文件开头 | 只读已有文件 |
| `"w"` | 否 | 存在则清空 | 文件开头 | 重新写入文件 |
| `"a"` | 否 | 保留 | 写入总在末尾 | 追加内容 |
| `"r+"` | 是 | 保留 | 文件开头 | 读写已有文件 |
| `"w+"` | 否 | 存在则清空 | 文件开头 | 重新建立并读写 |
| `"a+"` | 否 | 保留 | 读取位置依实现规则，写入在末尾 | 读取并追加 |

最需要警惕的是 `"w"` 和 `"w+"`：若文件已经存在，成功打开会把原内容截断为空。不要把“写模式”误解为“在原内容后继续写”。追加应使用 `"a"` 或 `"a+"`。

## 五、文本模式与二进制模式

在模式字符串中加入 `b` 表示二进制模式：

```c
fopen("image.bin", "rb");
fopen("records.bin", "wb");
fopen("records.bin", "ab");
```

在某些系统上，文本模式会对换行等内容进行转换；二进制模式按字节处理。类 Unix 系统中两者可能没有明显差别，但可移植程序仍应根据数据性质选择模式。

- 人可以直接阅读、需要跨环境交换的数据，常使用文本格式；
- 图片、压缩数据或明确设计的二进制格式，使用二进制模式。

## 六、相对路径与当前工作目录

```c
fopen("data.txt", "r");
```

`data.txt` 是相对路径。它通常相对于程序启动时的当前工作目录，而不一定是源文件所在目录或可执行文件所在目录。

这解释了一个常见现象：文件明明放在项目中，程序却报告找不到。此时应检查 IDE 或终端运行程序时的工作目录。

绝对路径能明确位置，但把个人计算机上的绝对路径写死会降低可移植性。学习项目通常使用清楚的相对路径，并确认运行目录。

## 七、使用 fprintf 写文本

`fprintf` 与 `printf` 类似，只是第一个参数指定输出到哪个文件流：

```c
#include <stdio.h>

int main(void) {
    FILE *file = fopen("scores.txt", "w");

    if (file == NULL) {
        perror("scores.txt");
        return 1;
    }

    if (fprintf(file, "%d %s %.1f\n", 1001, "Li_Ming", 92.5) < 0) {
        printf("写入文件失败\n");
        fclose(file);
        return 1;
    }

    if (fclose(file) != 0) {
        printf("关闭文件失败\n");
        return 1;
    }

    return 0;
}
```

`fprintf` 失败时返回负值。关闭文件也可能失败，例如缓冲数据最终写入存储设备时发生错误，因此重要数据应检查 `fclose` 返回值。

## 八、perror 提供系统错误信息

当标准库函数设置了错误状态时，可使用 `perror` 输出说明：

```c
FILE *file = fopen("scores.txt", "r");

if (file == NULL) {
    perror("打开 scores.txt 失败");
    return 1;
}
```

输出可能包含“文件不存在”或“权限不足”等系统信息。`perror` 的文字会因操作系统和语言环境不同而变化。

若需要进一步处理错误码，可使用 `<errno.h>` 中的 `errno`，但不要在没有函数失败依据时随意读取它，因为成功函数不一定把旧错误码清零。

## 九、使用 fputs 和 fputc 写文本

### 写一个字符串

```c
if (fputs("C language\n", file) == EOF) {
    printf("写入失败\n");
}
```

`fputs` 不会像 `puts` 那样自动补充换行，需要自行写 `\n`。

### 写一个字符

```c
if (fputc('A', file) == EOF) {
    printf("写入失败\n");
}
```

根据数据单位选择函数：格式化记录用 `fprintf`，整段字符串用 `fputs`，单个字符用 `fputc`。

## 十、使用 fgets 按行读取

`fgets` 最多读取“数组容量减 1”个字符，并在末尾补 `\0`：

```c
#include <stdio.h>

int main(void) {
    FILE *file = fopen("data.txt", "r");
    if (file == NULL) {
        perror("data.txt");
        return 1;
    }

    char line[100];

    while (fgets(line, sizeof line, file) != NULL) {
        printf("%s", line);
    }

    if (ferror(file)) {
        printf("读取过程中发生错误\n");
    }

    fclose(file);
    return 0;
}
```

若一行能装入数组，`fgets` 通常会把换行符也保存下来。若行太长，一次调用只得到该行的一部分，下一次调用继续读取剩余内容。

循环结束可能是正常到达文件末尾，也可能是读取错误，所以之后使用 `ferror` 判断。

## 十一、不要使用 while (!feof(file))

错误模式：

```c
while (!feof(file)) {
    fgets(line, sizeof line, file);
    printf("%s", line);
}
```

文件末尾标志只有在读取操作尝试越过末尾之后才会设置。上述写法可能在最后一次读取失败后仍使用旧数据。

正确原则是：用读取函数本身的返回值控制循环。

```c
while (fgets(line, sizeof line, file) != NULL) {
    printf("%s", line);
}
```

对 `fscanf`、`fread`、`fgetc` 也应采用同样思想。

## 十二、使用 fgetc 逐字符读取

```c
int ch;

while ((ch = fgetc(file)) != EOF) {
    putchar(ch);
}
```

变量应使用 `int`，而不是 `char`。原因是 `fgetc` 需要同时返回所有可能的 `unsigned char` 值和特殊值 `EOF`，`char` 未必能区分这些情况。

循环结束后仍可使用 `ferror(file)` 判断是否发生读取错误。

## 十三、使用 fscanf 读取格式化文本

假设文件内容为：

```text
1001 Li_Ming 92.5
1002 Wang_Hua 88.0
```

可以读取：

```c
int id;
char name[20];
double score;

while (fscanf(file, "%d %19s %lf", &id, name, &score) == 3) {
    printf("%d %s %.1f\n", id, name, score);
}
```

返回值表示成功赋值的项目数。只有等于 3 时，一条记录才完整读取。

注意：

- `%19s` 为 `name[20]` 留出结尾 `\0`；
- 数组名 `name` 已表示首元素地址，不写 `&name`；
- 读取 `double` 使用 `%lf`；
- `%s` 不能读取包含空格的姓名，文件格式必须明确约定。

对于复杂或不可信文本，通常先用 `fgets` 读取整行，再用 `sscanf` 或其他方法解析，更容易发现格式错误并报告具体行号。

## 十四、EOF、feof 与 ferror

`EOF` 是表示输入结束或某些输入失败的特殊宏值，不是文件中一定真实存在的字符。

读取结束后可判断：

```c
if (feof(file)) {
    printf("正常到达文件末尾\n");
} else if (ferror(file)) {
    printf("读取文件时发生错误\n");
}
```

应先执行一次失败的读取，再根据流状态判断原因。`clearerr(file)` 可以清除文件末尾和错误标志，但普通顺序读取通常不需要。

## 十五、标准输入、输出和错误流

程序启动时通常已经有三个标准流：

- `stdin`：标准输入；
- `stdout`：标准输出；
- `stderr`：标准错误。

例如：

```c
fprintf(stdout, "正常结果\n");
fprintf(stderr, "错误信息\n");
```

`printf(...)` 相当于向 `stdout` 进行格式化输出。把错误信息写到 `stderr`，可以让正常输出和诊断信息分别重定向或处理。

## 十六、缓冲与 fflush

文件输出通常先进入内存缓冲区，再由标准库批量写入外部设备，以提高效率。`fclose` 会尝试刷新缓冲区并关闭流。

可以主动刷新输出流：

```c
if (fflush(file) == EOF) {
    printf("刷新文件失败\n");
}
```

`fflush` 主要用于输出流。不要把 `fflush(stdin)` 当成清空输入的可移植标准方法，它在标准 C 中没有这种通用含义。

## 十七、文件位置

每个打开的文件流维护当前位置。顺序读取或写入后，位置会向后移动。

常见函数包括：

```c
long position = ftell(file);
fseek(file, 0, SEEK_SET);
rewind(file);
```

- `ftell` 获取当前位置表示；
- `fseek` 尝试移动到指定位置；
- `rewind` 回到文件开头并清除相关状态标志。

`SEEK_SET`、`SEEK_CUR`、`SEEK_END` 分别表示相对文件开头、当前位置和末尾。文本流中的任意字节偏移并非在所有系统上都具有简单可移植含义，初学阶段优先使用顺序读写和回到开头。

## 十八、二进制写入 fwrite

```c
int values[] = {10, 20, 30, 40};
size_t count = sizeof values / sizeof values[0];

FILE *file = fopen("values.bin", "wb");
if (file == NULL) {
    return 1;
}

size_t written = fwrite(values, sizeof values[0], count, file);
if (written != count) {
    printf("只写入了部分数据\n");
}

fclose(file);
```

`fwrite` 参数依次表示：数据起始地址、单个元素大小、元素个数和目标流。返回值是成功写入的元素个数。

## 十九、二进制读取 fread

```c
int values[4];

FILE *file = fopen("values.bin", "rb");
if (file == NULL) {
    return 1;
}

size_t read_count = fread(values, sizeof values[0], 4, file);

for (size_t i = 0; i < read_count; i++) {
    printf("%d\n", values[i]);
}

if (read_count < 4 && ferror(file)) {
    printf("读取发生错误\n");
}

fclose(file);
```

返回值小于请求数量可能是到达文件末尾，也可能是错误，应结合 `feof` 或 `ferror` 判断。

## 二十、直接保存结构体的局限

可以使用 `fwrite` 写出结构体的内存表示，但这种文件不一定适合长期保存或跨平台交换：

- 结构体可能含有填充字节；
- 不同平台的整数大小和字节顺序可能不同；
- 浮点表示可能存在差异；
- 指针成员写入的只是一次运行中的地址，重新读取通常没有意义；
- 修改结构体成员后，旧文件格式可能不再兼容。

学习实验可以在同一程序和环境中读写简单、无指针结构体；正式持久化应设计明确文件格式，逐字段保存，并考虑版本与范围检查。

## 二十一、资源清理与提前返回

打开文件后，所有离开函数的路径都应考虑关闭：

```c
FILE *file = fopen("data.txt", "r");
if (file == NULL) {
    return 1;
}

if (some_error) {
    fclose(file);
    return 1;
}

fclose(file);
return 0;
```

函数分支较多时，可以集中到一个清理区域，或把读写步骤拆成职责清楚的小函数。核心要求是所有权明确：成功打开文件的代码负责在适当时机关闭它。

## 二十二、常见错误与原因

### 1. 不检查 fopen 返回值

把 `NULL` 传给文件函数会造成严重错误。打开后必须立即检查。

### 2. 误用 w 模式清空文件

需要保留原内容并追加时应使用 `a`，而不是 `w`。

### 3. 忘记关闭文件

会泄漏资源，也可能使缓冲数据没有完成写入。

### 4. 使用 while (!feof(file))

文件末尾状态在读取失败后才建立。应使用读取函数返回值控制循环。

### 5. 忽略 fscanf 的返回值

格式错误时部分变量可能没有更新，继续使用会产生错误结果。

### 6. 用 char 保存 fgetc 返回值

可能无法正确区分普通字节和 `EOF`，应使用 `int`。

### 7. 假设相对路径相对于源文件

它通常相对于程序当前工作目录。

### 8. 把内存中的结构体直接当成通用文件格式

结构体布局和指针值不适合直接跨平台持久化。

## 二十三、与相关知识的联系

- C14 输入输出：文件函数与控制台输入输出共享“流”的思想。
- C29 字符串：路径、模式字符串、文本行和字段都使用字符数据。
- C32 指针基础：文件由 `FILE *` 表示，缓冲区也通过地址传入。
- C36 结构体：记录型数据常按结构体组织，再设计文本或二进制格式。
- C43 错误与调试：文件打开、读取、写入和关闭都需要检查失败信息。
- C45 小型程序设计：文件可为完整程序提供保存与加载功能。

## 分层练习

1. 使用 `fprintf` 把姓名和成绩写入文本文件，再用文本编辑器观察结果。
2. 使用 `fgets` 逐行读取文件，并统计行数。
3. 使用 `fscanf` 读取多条成绩记录，检查每次返回值并计算平均分。
4. 使用 `fwrite` 和 `fread` 保存、读取一个整数数组，并验证元素个数。
5. 为“文件不存在、记录格式错误、写入失败”分别设计清楚的错误处理路径。

## 小结

文件读写的核心是管理一个可能失败的外部资源。程序应选择正确模式，立即检查 `fopen`，根据读写函数返回值推进处理，并在所有路径上关闭文件。文本格式便于阅读与交换，二进制格式效率较高但需要明确设计，不能简单把内存布局当成永久格式。

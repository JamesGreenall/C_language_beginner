# C41. 头文件组织

## 节点定位

- 所属模块：预处理与多文件组织
- 学习难度：综合应用
- 建议学习时间：120-150 分钟
- 典型用途：把程序拆分为职责清楚的模块，并通过头文件公开模块接口。

## 学习目标

- 理解源文件、头文件、翻译单元、目标文件和链接之间的关系。
- 区分声明与定义，并知道它们通常分别放在哪里。
- 会为一个简单模块编写 `.h` 接口文件和 `.c` 实现文件。
- 会使用头文件保护防止同一翻译单元中的重复包含。
- 理解“头文件应当自包含”和“源文件包含自己的头文件”的原因。
- 能正确组织结构体、枚举、宏、函数声明及必要的外部变量声明。
- 初步识别循环包含、重复定义和缺少链接对象文件等问题。

## 一、为什么要把程序拆成多个文件

小程序可以全部写在 `main.c` 中。随着功能增加，单个文件会出现以下问题：

- 很难快速找到某项功能；
- 多人修改同一文件容易发生冲突；
- 内部实现细节暴露在所有代码旁边；
- 修改一个模块时不容易判断影响范围；
- 公共类型和函数声明容易重复书写并产生不一致。

可以按功能拆分：

```text
main.c          程序入口和总体流程
student.c       学生数据处理的实现
student.h       学生模块对外提供的接口
file_utils.c    文件处理的实现
file_utils.h    文件处理模块的接口
```

每个模块通常由一个头文件和一个源文件组成。头文件回答“外部可以使用什么”，源文件回答“这些功能内部如何实现”。

## 二、接口与实现

接口是模块向其他代码公开的内容，例如：

- 函数声明；
- 公共结构体或枚举类型；
- 调用者需要使用的常量；
- 必要的外部对象声明。

实现是完成这些功能的具体代码，例如算法步骤、内部辅助函数和仅供模块使用的数据。

将二者分开有两个好处：

1. 使用者只需阅读头文件就能知道如何调用模块；
2. 实现可以在不改变接口的情况下调整，其他模块通常无需修改。

## 三、声明与定义的区别

声明告诉编译器某个名称及其类型：

```c
int add(int a, int b);
```

函数原型说明 `add` 接收两个 `int` 并返回 `int`，但没有提供函数体。

定义真正提供函数实现：

```c
int add(int a, int b) {
    return a + b;
}
```

一般规则是：

- 允许在多个源文件中看到相同且一致的声明；
- 一个具有外部链接的普通函数或全局变量，在整个程序中通常只能有一个定义；
- 头文件主要放声明，源文件主要放定义。

结构体类型定义和 `typedef` 通常需要出现在头文件中，因为使用该类型的每个源文件都必须看到完整且一致的类型描述。

## 四、什么是翻译单元

每个 `.c` 文件连同它通过 `#include` 得到的内容，经过预处理后形成一个翻译单元。编译器通常分别编译每个翻译单元：

```text
main.c + 所含头文件      -> main.o
math_utils.c + 所含头文件 -> math_utils.o
```

随后链接器把目标文件组合起来：

```text
main.o + math_utils.o -> 可执行程序
```

一个源文件中的函数调用只要提前看到了正确声明，就可以通过编译；函数定义是否真的存在，通常要到链接阶段才能最终确认。

因此常见错误可粗略区分为：

- 编译错误：语法、类型或声明问题；
- 链接错误：声明过但找不到定义，或同名定义出现多次。

## 五、一个完整的三文件模块

下面建立简单的数学工具模块。

### math_utils.h

```c
#ifndef MATH_UTILS_H
#define MATH_UTILS_H

int add(int a, int b);
int maximum(int a, int b);

#endif
```

头文件声明模块提供的两个函数。

### math_utils.c

```c
#include "math_utils.h"

int add(int a, int b) {
    return a + b;
}

int maximum(int a, int b) {
    return a > b ? a : b;
}
```

源文件包含自己的头文件并实现函数。

### main.c

```c
#include <stdio.h>

#include "math_utils.h"

int main(void) {
    printf("3 + 5 = %d\n", add(3, 5));
    printf("较大值：%d\n", maximum(12, 9));
    return 0;
}
```

`main.c` 通过头文件得知函数接口，不需要知道函数内部如何实现。

## 六、编译并链接多文件程序

可以直接把两个源文件交给 GCC：

```text
gcc main.c math_utils.c -Wall -Wextra -o program
```

这条命令会分别处理源文件，并链接为一个可执行程序。

也可以分步执行：

```text
gcc -c main.c -Wall -Wextra
gcc -c math_utils.c -Wall -Wextra
gcc main.o math_utils.o -o program
```

其中：

- `-c` 表示只编译为目标文件，暂不链接；
- `main.o` 和 `math_utils.o` 是常见的目标文件名；
- 最后一条命令执行链接。

Windows 中某些工具链可能使用 `.obj` 作为目标文件扩展名，但原理相同。

## 七、为什么实现文件要包含自己的头文件

`math_utils.c` 应首先包含：

```c
#include "math_utils.h"
```

这样编译器可以比较头文件声明与函数定义：

```c
// 头文件中
int add(int a, int b);

// 源文件中
int add(int a, int b) {
    return a + b;
}
```

如果实现错误地写成不同参数类型，编译器通常能在该源文件中及时报告冲突。若实现文件不包含自己的头文件，这种不一致可能拖到其他文件编译或程序运行时才暴露。

一种常见包含顺序是：

1. 当前 `.c` 文件对应的头文件；
2. C 标准库头文件；
3. 其他第三方或项目头文件。

先包含自己的头文件也能检验该头文件是否缺少必要依赖。

## 八、什么是头文件保护

同一个头文件可能通过不同路径被多次包含：

```text
main.c 包含 student.h
main.c 包含 report.h
report.h 又包含 student.h
```

如果 `student.h` 没有保护，其中的结构体定义可能在同一个翻译单元出现两次，引发重定义错误。

标准的包含保护形式为：

```c
#ifndef STUDENT_H
#define STUDENT_H

/* 头文件内容 */

#endif
```

第一次包含时，`STUDENT_H` 尚未定义，所以处理内容并定义该宏。第二次包含时，条件不成立，内容被跳过。

## 九、头文件保护名称如何设计

保护宏应尽量唯一，通常根据项目名、目录和文件名组成：

```c
#ifndef SCHOOL_STUDENT_H
#define SCHOOL_STUDENT_H

/* declarations */

#endif  // SCHOOL_STUDENT_H
```

不建议使用以下划线开头并包含大写字母的名称，因为某些形式保留给实现使用。项目自己的大写前缀加文件名通常更稳妥。

文件末尾的注释不是语法必需，但在较长头文件中可以说明 `#endif` 对应哪个条件。

## 十、#pragma once

许多编译器支持：

```c
#pragma once
```

它也用于防止头文件重复包含，写法简洁。但 `#pragma once` 不是所有 C 标准版本统一规定的可移植机制。

若学习目标是掌握标准且普遍适用的方式，应优先理解 `#ifndef/#define/#endif` 头文件保护。实际项目可以遵循所用工具链和团队规范。

## 十一、头文件中适合放什么

常见的公共内容包括：

### 1. 函数声明

```c
double average(const int values[], int length);
```

### 2. 结构体和枚举类型

```c
typedef enum StudentStatus {
    STUDENT_ACTIVE,
    STUDENT_GRADUATED
} StudentStatus;

typedef struct Student {
    int id;
    char name[20];
    StudentStatus status;
} Student;
```

### 3. 调用者需要的常量宏

```c
#define STUDENT_NAME_CAPACITY 20
```

宏名称应带模块前缀，降低冲突风险。

### 4. 必要的外部对象声明

```c
extern const char *school_name;
```

外部全局对象会增加模块耦合，应少用，并明确其只读性和初始化位置。

## 十二、头文件中通常不应放什么

### 1. 普通函数定义

```c
int add(int a, int b) {
    return a + b;
}
```

若这个头文件被多个 `.c` 文件包含，链接时可能出现多个同名函数定义。

### 2. 普通全局变量定义

```c
int student_count = 0;
```

每个包含者都可能产生一个定义，导致重复定义错误。

### 3. 只供实现内部使用的细节

内部辅助函数、私有常量和实现数据应留在对应 `.c` 文件中，避免其他模块依赖它们。

`static inline` 函数和某些特殊常量定义可以放在头文件中，但涉及更具体的链接与内联规则。初学阶段先遵守“头文件放接口声明，源文件放普通定义”这一可靠原则。

## 十三、全局变量的声明与定义

若确实需要一个由多个源文件共享的全局变量，应在头文件中使用 `extern` 声明：

### counter.h

```c
#ifndef COUNTER_H
#define COUNTER_H

extern int global_count;

void increase_count(void);

#endif
```

在且仅在一个源文件中定义：

### counter.c

```c
#include "counter.h"

int global_count = 0;

void increase_count(void) {
    global_count++;
}
```

`extern int global_count;` 主要是声明，`int global_count = 0;` 是定义并提供存储空间。

不过，直接公开可修改全局变量会使任何模块都能改变它。更好的设计通常是把变量留在 `.c` 文件中，并通过函数访问。

## 十四、用 static 隐藏实现细节

只供当前 `.c` 文件使用的辅助函数可以声明为 `static`：

```c
static int is_valid_score(int score) {
    return score >= 0 && score <= 100;
}
```

文件作用域的 `static` 函数具有内部链接，不会作为整个程序的公共名称提供给其他翻译单元。

因此：

- 公共函数声明放在 `.h` 中；
- 公共函数定义放在 `.c` 中；
- 私有辅助函数用 `static` 定义在 `.c` 中，不放入公共头文件。

这种组织方式能够清楚区分模块接口与实现细节。

## 十五、头文件应当自包含

一个头文件应能在没有特殊包含顺序的情况下被正常使用。例如，若接口中使用 `size_t`，头文件自己应包含定义它的标准头文件：

```c
#ifndef BUFFER_H
#define BUFFER_H

#include <stddef.h>

void clear_buffer(char *buffer, size_t size);

#endif
```

不应要求使用者必须先包含 `<stddef.h>` 再包含 `buffer.h`。这种隐含顺序依赖容易导致“在某个源文件能编译，换个顺序就失败”。

检验方法是建立最小源文件：

```c
#include "buffer.h"

int main(void) {
    return 0;
}
```

若它能独立通过编译，说明头文件至少具备基本自包含性。

## 十六、在头文件中包含所需依赖

若公共结构体直接包含另一个结构体对象，就必须看到对方完整定义：

```c
#include "date.h"

typedef struct Student {
    int id;
    Date birthday;
} Student;
```

此时 `Student` 的大小依赖 `Date` 的完整内容，所以需要包含 `date.h`。

不要依赖某个其他头文件“碰巧已经间接包含了 date.h”。直接使用某项声明或类型的头文件，应直接包含提供它的头文件。这常被概括为“使用什么，就包含什么”。

## 十七、前向声明减少不必要包含

若头文件只使用某结构体的指针，不需要知道结构体大小，可以进行前向声明：

```c
struct Student;

void print_student(const struct Student *student);
```

这告诉编译器 `struct Student` 是一种结构体类型，但暂时不说明成员。

可以声明指针，因为指针大小已知；不能直接声明该类型的对象成员：

```c
struct Student;

struct Report {
    struct Student *owner;  // 可以
    // struct Student data; // 不可以：类型尚不完整
};
```

前向声明可以减少头文件相互包含，但不应为了追求最少包含而让代码过度复杂。

## 十八、循环包含问题

假设 `student.h` 包含 `course.h`，而 `course.h` 又包含 `student.h`。头文件保护能阻止无限展开，但不一定能解决类型在使用位置尚未完整定义的问题。

常见处理方式包括：

- 只需要指针时使用结构体前向声明；
- 把双方共同需要的类型移到第三个基础头文件；
- 重新设计模块依赖，避免两个模块互相了解过多细节。

头文件保护解决的是“重复包含”，不是所有“循环依赖”设计问题。

## 十九、不要在头文件中使用 using 式隐含状态

C 头文件会进入每个包含它的翻译单元，因此头文件中的宏、类型名和外部声明会影响所有使用者。公共头文件应尽量减少意外影响：

- 不定义过于通用的宏名；
- 不随意 `#undef` 别人可能使用的宏；
- 不依赖包含顺序改变接口；
- 不放置执行语句；
- 不暴露没有必要公开的内部名称。

头文件越稳定、越独立，模块之间越容易组合。

## 二十、头文件路径与项目目录

一个简单项目可以采用：

```text
project/
    include/
        student.h
    src/
        student.c
        main.c
```

编译时把 `include` 加入搜索路径：

```text
gcc -Iinclude src/main.c src/student.c -Wall -Wextra -o program
```

小型练习也可以把 `.h` 和 `.c` 放在同一目录。目录结构应服务于清楚的模块边界，不必为了形式提前建立过多层级。

## 二十一、完整示例：学生模块

### student.h

```c
#ifndef SCHOOL_STUDENT_H
#define SCHOOL_STUDENT_H

#include <stddef.h>

#define STUDENT_NAME_CAPACITY 20

typedef struct Student {
    int id;
    char name[STUDENT_NAME_CAPACITY];
    double score;
} Student;

void student_print(const Student *student);
double student_average(const Student students[], size_t count);

#endif  // SCHOOL_STUDENT_H
```

### student.c

```c
#include "student.h"

#include <stdio.h>

void student_print(const Student *student) {
    if (student == NULL) {
        return;
    }

    printf("%d %s %.1f\n",
           student->id,
           student->name,
           student->score);
}

double student_average(const Student students[], size_t count) {
    if (students == NULL || count == 0) {
        return 0.0;
    }

    double sum = 0.0;

    for (size_t i = 0; i < count; i++) {
        sum += students[i].score;
    }

    return sum / count;
}
```

### main.c

```c
#include <stdio.h>

#include "student.h"

int main(void) {
    Student students[] = {
        {1001, "Li Ming", 92.5},
        {1002, "Wang Hua", 88.0},
        {1003, "Chen Yu", 95.5}
    };
    size_t count = sizeof students / sizeof students[0];

    for (size_t i = 0; i < count; i++) {
        student_print(&students[i]);
    }

    printf("平均分：%.2f\n", student_average(students, count));
    return 0;
}
```

编译：

```text
gcc main.c student.c -std=c11 -Wall -Wextra -o student_program
```

## 二十二、如何判断内容应放在哪个文件

可以按照以下问题判断：

1. 其他源文件是否必须知道这个名称？
2. 它是接口声明，还是具体实现？
3. 使用者是否需要看到类型的完整成员？
4. 这个常量是否属于模块公共约定？
5. 这个函数是否只服务于当前实现文件？

通常：

| 内容 | 建议位置 |
| --- | --- |
| 公共函数声明 | `.h` |
| 公共结构体、枚举、类型别名 | `.h` |
| 公共常量宏 | `.h` |
| 普通函数定义 | `.c` |
| 私有 `static` 辅助函数 | `.c` |
| 内部常量和实现数据 | `.c` |
| 程序入口 `main` | 专门的 `.c` 文件 |

## 二十三、常见错误与诊断

### 1. 找不到头文件

常见提示类似“no such file or directory”。检查文件名、相对位置、大小写和 `-I` 搜索路径。

### 2. 函数出现 undefined reference

头文件声明使编译通过，但链接器找不到函数定义。检查实现文件是否存在，以及编译命令是否包含该 `.c` 或对应目标文件。

### 3. multiple definition

同名函数或全局变量被定义多次。常见原因是在头文件中放了普通定义，或多个源文件各自定义了同一个外部对象。

### 4. conflicting types

函数声明和定义不一致。让实现文件包含自己的头文件，可以更早发现此问题。

### 5. unknown type name

使用类型前没有包含提供它的头文件，或两个头文件存在不正确的循环依赖。

### 6. 头文件有保护仍然链接重定义

头文件保护只防止同一头文件在一个翻译单元中重复展开。它不能使放在头文件中的普通外部函数定义自动变成“整个程序只有一份”。

- C23 函数声明与原型：公共函数原型通常放入头文件。
- C36 结构体：供多个模块使用的结构体类型通常定义在头文件中。
- C38 typedef 类型别名：公共类型别名通常作为模块接口的一部分。
- C39 预处理指令：`#include` 和条件编译实现头文件引入与保护。

## 分层练习

1. 建立 `math_utils.h`、`math_utils.c` 和 `main.c`，实现并调用加法与最大值函数。
2. 为头文件添加唯一的包含保护，并在同一源文件中有意包含两次，验证仍可编译。
3. 把 `Student` 类型与相关函数整理为独立模块，使用命令同时编译两个源文件。
4. 故意漏掉实现文件，观察链接错误；再加入实现文件并说明错误为何消失。
5. 设计两个互相有关的结构体，分别尝试直接包含和前向声明，判断何时需要完整类型。

## 小结

头文件用于公开稳定接口，源文件用于保存具体实现。每个源文件经过预处理后独立编译，最终由链接器组合。可靠的头文件应具有包含保护、能够自包含、只公开必要内容，并与对应实现保持一致。掌握声明、定义、编译和链接的分工，才能真正理解多文件 C 程序。

# C39. 预处理指令

## 节点定位

- 所属模块：预处理与多文件组织
- 学习难度：综合应用
- 建议学习时间：40-60 分钟
- 典型用途：在 C 程序中正确理解和使用“预处理指令”。

## 学习目标

- 能说清楚“预处理指令”解决的具体问题。
- 能在一段 C 代码中识别与“预处理指令”有关的语法现象。
- 能独立写出一个包含该知识点的最小示例程序。
- 能说明它与前置知识点、后续知识点之间的关系。

## 初学者导读

预处理发生在正式编译之前，用于处理头文件包含、宏替换和条件编译等内容。理解预处理有助于掌握 C 程序从文本到可编译代码的准备过程。

## 关键术语说明

- 预处理：编译前先做的文本处理。
- `#include`：把头文件内容引入当前文件。
- `#define`：定义宏替换规则。
- 条件编译：根据条件决定哪些代码参与编译。
- 预处理结果：处理后交给编译器的代码。

## 核心概念

预处理发生在正式编译之前，用于包含头文件、宏替换、条件编译等。

## 关键内容

- `#include` 包含头文件。
- `#define` 定义宏。
- `#if`、`#ifdef`、`#ifndef` 用于条件编译。
- 预处理指令以 `#` 开头。

## 示例

```c
#include <stdio.h>
#define MAX_SIZE 100
```

## 代码逐行解释

- `#include <stdio.h>`：预处理阶段会引入标准头文件内容。
- `#define MAX_SIZE 100`：把代码里的 `MAX_SIZE` 替换成 `100`。
- 这些指令发生在正式编译之前。
- 预处理指令通常不以分号结尾。

## 常见错误

- 以为宏有类型检查。
- 头文件重复包含。
- 宏替换导致表达式优先级问题。

## 初学者常见误区

- 预处理指令以 `#` 开头，通常不是普通 C 语句。
- `#include` 不是复制粘贴给人看，而是编译前由工具处理。
- 条件编译能让不同环境使用不同代码。

## 语法格式

```c
#include <头文件>
#include "自定义头文件"
#define 名字 替换内容
#ifdef 条件
#endif
```

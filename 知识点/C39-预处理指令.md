# C39. 预处理指令

## 节点定位

- 所属模块：预处理与多文件组织
- 学习难度：综合应用
- 建议学习时间：90-120 分钟
- 典型用途：在正式编译前包含头文件、控制代码是否参与编译，并完成宏替换等准备工作。

## 学习目标

- 理解预处理在 C 程序编译流程中的位置。
- 区分预处理指令与普通 C 语句。
- 掌握 `#include` 的两种常见形式及基本查找差异。
- 会使用 `#if`、`#ifdef`、`#ifndef`、`#elif`、`#else` 和 `#endif` 进行条件编译。
- 理解预处理宏与编译器命令行宏定义的基本作用。
- 会使用常见预定义宏和 `#error` 辅助诊断。
- 能识别条件不配对、错误包含方式和跨行指令等常见问题。

## 一、预处理处于什么位置

一个 C 源文件从文本变成可执行程序，通常要经历以下过程：

```text
源代码
  ↓
预处理：处理 #include、#define、条件编译等
  ↓
编译：检查 C 语法和类型，生成目标代码
  ↓
链接：把多个目标文件及所需库组合起来
  ↓
可执行程序
```

预处理发生在正式编译之前。它主要处理源代码中的预处理指令，并把处理结果交给编译器。

例如：

```c
#define LIMIT 100

int data[LIMIT];
```

预处理阶段会按照宏规则处理 `LIMIT`，编译器随后看到相应的 C 代码。宏定义本身不是运行时执行的语句，不会在程序运行时“给 LIMIT 赋值”。

## 二、预处理指令与普通语句的区别

预处理指令通常以 `#` 开头：

```c
#include <stdio.h>
#define LIMIT 100
```

普通 C 语句则由编译器处理，并可能在程序运行时执行：

```c
printf("Hello\n");
count = count + 1;
```

二者有几个明显区别：

- 预处理指令在编译前处理，普通语句由编译器分析；
- 预处理指令通常不写分号；
- 预处理指令可以决定某段代码是否交给编译器；
- 预处理阶段不具备普通 C 类型系统的完整检查能力。

虽然习惯上把 `#` 写在行首，但标准允许其前面出现空白字符。为了统一和易读，通常仍从行首开始书写。

## 三、#include 的作用

`#include` 让预处理器在当前位置处理指定头文件的内容：

```c
#include <stdio.h>
```

包含 `<stdio.h>` 后，编译器才能看到 `printf`、`scanf`、`FILE` 等标准库接口的声明。

可以把头文件包含初步理解为“在这里引入头文件所提供的声明”。它在效果上类似把相关文本展开到当前位置，但实际实现可能使用更高效的内部机制。

`#include` 并不会自动把函数的实现复制进程序。标准库函数的实现通常在链接阶段从相应库中获得；自定义函数的实现则通常位于另一个 `.c` 文件中。

## 四、尖括号与双引号

### 1. 包含标准库或系统头文件

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
```

尖括号通常用于编译环境提供的头文件。编译器按照系统头文件搜索路径查找。

### 2. 包含项目自己的头文件

```c
#include "student.h"
```

双引号通常用于项目头文件。实现一般会先从当前源文件附近或项目指定路径查找，找不到时再按实现规则查找其他目录。

不同编译器的完整搜索规则可能不同，可以通过编译选项添加项目头文件目录。例如 GCC 常使用 `-I` 指定额外目录：

```text
gcc -Iinclude main.c student.c -o program
```

初学阶段可以记住：标准头文件通常用 `<...>`，自己编写的头文件通常用 `"..."`。

## 五、为什么不能省略标准头文件

```c
printf("Hello\n");
```

函数调用需要与正确的函数声明相匹配。若没有包含 `<stdio.h>`，编译器无法按标准声明检查 `printf` 的参数和返回类型。在现代 C 标准下，这通常会产生诊断信息，也可能导致程序行为错误。

因此，不应因为某个编译器“暂时还能编译”就省略需要的头文件。使用哪个标准库接口，就应包含声明该接口的标准头文件。

## 六、#define 与 #undef 的位置

`#define` 定义宏，C40 将详细说明替换规则：

```c
#define MAX_STUDENTS 50
```

宏从定义位置开始生效，直到：

- 遇到相应的 `#undef`；
- 当前预处理翻译单元结束。

可以取消宏定义：

```c
#undef MAX_STUDENTS
```

取消后，后续代码中 `MAX_STUDENTS` 不再作为该宏展开。频繁定义和取消同名宏容易增加理解难度，应谨慎使用。

## 七、什么是条件编译

普通 `if` 决定程序运行时执行哪个分支；条件编译则在编译前决定哪些源代码会交给编译器。

```c
#ifdef DEBUG
printf("调试信息：count = %d\n", count);
#endif
```

如果宏 `DEBUG` 已定义，`printf` 代码参与编译；如果没有定义，这段代码在预处理阶段被排除。

条件编译适用于：

- 控制调试代码；
- 适配不同操作系统或编译环境；
- 启用或关闭可选功能；
- 防止头文件重复包含；
- 在不满足编译条件时主动报错。

它不适合替代普通业务判断，因为被排除的代码根本不会进入最终程序。

## 八、#ifdef 与 #ifndef

### 1. 判断宏是否已定义

```c
#ifdef DEBUG
printf("调试模式\n");
#endif
```

`#ifdef DEBUG` 只判断宏名是否存在，不关心它替换成什么。

即使写成：

```c
#define DEBUG 0
```

`DEBUG` 仍然是“已定义”，所以 `#ifdef DEBUG` 条件成立。

### 2. 判断宏是否未定义

```c
#ifndef BUFFER_SIZE
#define BUFFER_SIZE 256
#endif
```

含义是：如果 `BUFFER_SIZE` 尚未定义，就为它提供默认定义。

`#ifndef` 也常用于头文件保护，防止同一个头文件内容在一次编译中被重复处理。

## 九、#if、#elif、#else 与 #endif

`#if` 可以判断预处理阶段可计算的整数常量表达式：

```c
#define LOG_LEVEL 2

#if LOG_LEVEL >= 3
printf("详细调试信息\n");
#elif LOG_LEVEL == 2
printf("一般运行信息\n");
#else
printf("只输出重要信息\n");
#endif
```

结构含义与 `if/else if/else` 类似，但发生时间不同：

- `#if`：开始条件编译；
- `#elif`：继续判断其他预处理条件；
- `#else`：处理其余情况；
- `#endif`：结束当前条件编译区域。

每个 `#if`、`#ifdef` 或 `#ifndef` 都必须与一个 `#endif` 配对。

## 十、defined 运算符

在 `#if` 中，可以用 `defined` 判断宏是否存在：

```c
#if defined(DEBUG)
printf("调试模式\n");
#endif
```

也可以组合多个条件：

```c
#if defined(DEBUG) && defined(VERBOSE)
printf("详细调试模式\n");
#endif
```

下面两种写法意义相同：

```c
#ifdef DEBUG
#if defined(DEBUG)
```

当条件较复杂时，`defined(...)` 通常更便于组合和阅读。

## 十一、未定义标识符在 #if 中的情况

在 `#if` 表达式中，完成宏展开后仍未定义为宏的普通标识符会按 0 处理。例如：

```c
#if FEATURE_LEVEL
/* 条件代码 */
#endif
```

如果 `FEATURE_LEVEL` 未定义，条件相当于 0。但这种写法可能隐藏拼写错误。更明确的写法是先判断是否已定义：

```c
#if defined(FEATURE_LEVEL) && FEATURE_LEVEL > 0
/* 条件代码 */
#endif
```

这样既表达存在性，也表达数值要求。

## 十二、从编译命令定义宏

编译器通常允许通过命令行定义宏。GCC 中可使用 `-D`：

```text
gcc main.c -DDEBUG -o main
```

这相当于在预处理时提前定义 `DEBUG`。也可以指定值：

```text
gcc main.c -DLOG_LEVEL=3 -o main
```

同一份源代码因此可以在不修改文件的情况下生成不同配置的程序。

还可以使用 `-U` 取消预先存在的宏定义，但普通入门项目较少需要。

## 十三、完整示例：控制调试输出

```c
#include <stdio.h>

#ifndef LOG_LEVEL
#define LOG_LEVEL 1
#endif

int main(void) {
    int score = 92;

#if LOG_LEVEL >= 2
    printf("调试：score 的值为 %d\n", score);
#endif

    printf("成绩：%d\n", score);
    return 0;
}
```

普通编译：

```text
gcc main.c -o main
```

此时 `LOG_LEVEL` 使用默认值 1，不包含调试输出。

指定更高日志级别：

```text
gcc main.c -DLOG_LEVEL=2 -o main
```

此时条件成立，编译出的程序包含调试输出。

## 十四、平台条件编译

不同环境可能提供表示平台的预定义宏。例如，某些编译器在 Windows 环境定义 `_WIN32`：

```c
#if defined(_WIN32)
    printf("Windows 环境\n");
#elif defined(__linux__)
    printf("Linux 环境\n");
#else
    printf("其他环境\n");
#endif
```

平台宏并非全部由 C 标准统一规定。使用前应查阅目标编译器文档，不要根据名称猜测。跨平台代码还应尽量把平台差异集中在少量模块中，避免条件编译散布在整个项目。

## 十五、常见预定义宏

编译器会提供一些标准预定义宏：

| 宏 | 常见含义 |
| --- | --- |
| `__FILE__` | 当前源文件名字符串 |
| `__LINE__` | 当前源代码行号整数 |
| `__DATE__` | 当前翻译日期字符串 |
| `__TIME__` | 当前翻译时间字符串 |
| `__STDC__` | 实现符合标准 C 时定义为相应值 |

示例：

```c
#include <stdio.h>

int main(void) {
    printf("位置：%s:%d\n", __FILE__, __LINE__);
    printf("编译日期：%s\n", __DATE__);
    printf("编译时间：%s\n", __TIME__);
    return 0;
}
```

`__FILE__` 和 `__LINE__` 常用于日志与错误定位。`__DATE__` 和 `__TIME__` 会随编译时间变化，不适合要求每次构建结果完全一致的场景。

## 十六、使用 #error 主动终止编译

当必要条件不满足时，可以使用 `#error` 产生编译错误：

```c
#ifndef APP_VERSION
#error APP_VERSION must be defined
#endif
```

若没有定义 `APP_VERSION`，编译会停止并显示错误消息。

它适合检查必要配置，而不是处理运行时输入错误。运行时问题应使用普通条件语句和错误处理机制。

## 十七、跨行预处理指令

预处理指令通常占一个逻辑行。若内容过长，可以在行末使用反斜杠 `\` 续行：

```c
#define PRINT_SUM(a, b) \
    printf("sum = %d\n", (a) + (b))
```

反斜杠必须是该物理行最后的有效字符，后面不要再添加空格或注释。续行容易因编辑格式出现隐蔽问题，所以仅在确有必要时使用。

## 十八、查看预处理结果

理解宏或包含问题时，可以查看预处理后的文本。GCC 常使用 `-E`：

```text
gcc -E main.c
```

结果通常很长，因为标准头文件也会被展开。可以先对只包含少量宏的短文件练习，观察：

- 宏名称如何被替换；
- 条件不成立的代码如何消失；
- 头文件声明如何进入翻译单元。

查看预处理结果是分析宏展开问题的有效方法。

## 十九、常见错误与原因

### 1. 在预处理指令后随意添加分号

```c
#define LIMIT 100;
```

分号会成为宏替换内容的一部分，可能导致使用位置出现多余分号。应写成 `#define LIMIT 100`。

### 2. 条件编译没有正确配对

遗漏 `#endif` 或嵌套层级混乱会导致预处理错误。较长条件块可在 `#endif` 后写注释说明对应条件：

```c
#endif  // DEBUG
```

### 3. 混淆 #ifdef DEBUG 与 #if DEBUG

`#ifdef DEBUG` 判断是否定义；`#if DEBUG` 判断展开后的数值是否非零。`#define DEBUG 0` 对前者为真，对后者为假。

### 4. 使用错误的包含形式

项目头文件通常用双引号，标准库头文件通常用尖括号。还要确保编译命令包含正确的搜索路径。

### 5. 认为被条件排除的代码仍会运行

被排除的文本不会进入编译结果，运行时自然不存在该代码。

### 6. 用条件编译掩盖大量重复代码

条件编译过多会形成多套难以同时测试的程序。应尽量把差异封装在少量清晰接口中。

- C01 开发环境与编译流程：预处理是源代码进入正式编译前的重要阶段。
- C02 源文件、头文件与程序结构：头文件通过 `#include` 提供声明。
- C40 宏定义：`#define` 的替换规则、参数宏及风险需要单独深入学习。
- C41 头文件组织：头文件保护依赖条件编译指令。

## 分层练习

1. 使用 `#include <stdio.h>` 编写输出程序，并说明为什么需要该头文件。
2. 定义 `DEBUG` 时输出调试信息，不定义时只输出正式结果。
3. 使用 `LOG_LEVEL` 和 `#if/#elif/#else` 实现三级日志配置。
4. 通过 GCC 的 `-D` 选项改变程序配置，并观察输出差异。
5. 使用 `__FILE__` 和 `__LINE__` 输出当前位置，再查看预处理结果确认宏展开情况。

## 小结

预处理在正式编译前处理源代码配置，包括头文件包含、宏定义和条件编译。它操作的是编译前文本和预处理记号，不是运行时数据。学习时应始终区分“是否进入编译”和“程序运行时是否执行”，并保持条件编译结构简洁、配对完整。

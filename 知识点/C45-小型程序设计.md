# C45. 小型程序设计

## 节点定位

- 所属模块：文件、调试与综合应用
- 学习难度：综合应用
- 建议学习时间：4-8 小时，可分多个阶段完成
- 典型用途：把变量、控制结构、函数、数组、结构体、文件和错误处理组合成完整程序。

## 学习目标

- 能把模糊任务整理为明确的输入、处理、输出和约束。
- 会根据对象和功能设计结构体、数组与函数接口。
- 能先实现最小可运行版本，再逐步增加功能。
- 会把输入、计算、显示和文件操作分开。
- 能为正常、边界和错误情况设计测试。
- 理解何时需要拆分头文件与源文件。
- 能完成一个结构清楚、可编译、可验证的小型 C 程序。

## 一、小型程序设计与单个语法题的区别

语法题通常只考查一个知识点，例如编写循环求和。小型程序需要同时回答：

- 程序究竟解决什么问题；
- 数据如何表示；
- 功能如何分成函数；
- 输入错误如何处理；
- 数据容量是否有限；
- 结果如何验证；
- 程序如何保存和继续读取数据；
- 文件增多后如何划分模块。

重点不再是“会不会写某条语句”，而是“能否让不同知识点形成一致、可维护的整体”。

## 二、从需求开始，而不是立即编码

以学生成绩管理程序为例，初始需求可以写成：

### 功能需求

1. 添加学生姓名和成绩；
2. 显示全部学生；
3. 按姓名查询学生；
4. 计算平均分、最高分和最低分；
5. 退出程序。

### 数据约束

- 最多保存 100 名学生；
- 姓名最多 19 个字符，暂不允许空格；
- 成绩范围为 0 到 100；
- 学生人数可以为 0；
- 相同姓名是否允许重复，需要提前规定。

### 错误情况

- 菜单输入不是整数；
- 学生数组已满；
- 成绩超出范围；
- 查询不到姓名；
- 统计时还没有学生。

需求越明确，后续条件判断和测试越容易确定。

## 三、识别程序中的对象

一名学生具有姓名和成绩，适合使用结构体：

```c
#define NAME_CAPACITY 20

typedef struct Student {
    char name[NAME_CAPACITY];
    double score;
} Student;
```

多名学生可以使用结构体数组：

```c
#define MAX_STUDENTS 100

Student students[MAX_STUDENTS];
int student_count = 0;
```

这里必须同时保存：

- 数组 `students`：提供最多 100 个位置；
- `student_count`：记录当前实际使用了多少个元素。

容量与实际数量不能混淆。合法记录下标是 0 到 `student_count - 1`。

## 四、先设计函数职责

根据需求可以得到：

```c
int add_student(Student students[], int *count);
void print_students(const Student students[], int count);
int find_student(const Student students[], int count, const char name[]);
int calculate_statistics(const Student students[], int count,
                         double *average,
                         double *minimum,
                         double *maximum);
void print_menu(void);
```

每个函数只承担一种主要职责：

- `add_student` 处理一条新增记录；
- `print_students` 只读并显示列表；
- `find_student` 返回匹配下标或失败标志；
- `calculate_statistics` 计算多个统计结果；
- `print_menu` 集中显示菜单。

函数接口先确定，主流程就能较清楚地组织起来。

## 五、输入、处理和输出应适当分离

下面的函数只负责计算，不在内部要求用户输入：

```c
int calculate_statistics(const Student students[], int count,
                         double *average,
                         double *minimum,
                         double *maximum) {
    if (students == NULL || count <= 0 ||
        average == NULL || minimum == NULL || maximum == NULL) {
        return 0;
    }

    double sum = students[0].score;
    *minimum = students[0].score;
    *maximum = students[0].score;

    for (int i = 1; i < count; i++) {
        double score = students[i].score;
        sum += score;

        if (score < *minimum) {
            *minimum = score;
        }
        if (score > *maximum) {
            *maximum = score;
        }
    }

    *average = sum / count;
    return 1;
}
```

这种函数容易测试，因为测试代码可以直接提供固定数组，不必模拟键盘输入。

## 六、先完成最小可运行版本

不要第一天就同时实现菜单、查询、排序、文件和动态内存。可以按里程碑推进：

### 版本 1：固定数据

- 在代码中创建 3 名学生；
- 打印列表；
- 计算平均分。

### 版本 2：键盘添加

- 添加菜单循环；
- 验证成绩范围；
- 检查数组容量。

### 版本 3：查询与统计

- 按姓名查询；
- 输出最高、最低和平均分；
- 处理空列表。

### 版本 4：文件保存与加载

- 设计文本记录格式；
- 检查文件和解析错误；
- 确定启动时是否自动加载。

### 版本 5：多文件组织

- 把公共类型和声明放入头文件；
- 把学生操作放入独立源文件；
- 主文件只保留菜单流程。

每完成一个版本都先测试，再进入下一阶段。

## 七、完整的基础版本

下面示例实现添加、列表、查询和统计。为了让重点集中在程序组织上，姓名暂定为不含空格的单词。

```c
#include <stdio.h>
#include <string.h>

#define MAX_STUDENTS 100
#define NAME_CAPACITY 20

typedef struct Student {
    char name[NAME_CAPACITY];
    double score;
} Student;

void print_menu(void) {
    printf("\n1. 添加学生\n");
    printf("2. 显示全部学生\n");
    printf("3. 查询学生\n");
    printf("4. 显示统计结果\n");
    printf("0. 退出\n");
    printf("请选择：");
}

void discard_line(void) {
    int ch;
    while ((ch = getchar()) != '\n' && ch != EOF) {
    }
}

int add_student(Student students[], int *count) {
    if (students == NULL || count == NULL || *count >= MAX_STUDENTS) {
        return 0;
    }

    Student new_student;

    printf("姓名（不含空格）：");
    if (scanf("%19s", new_student.name) != 1) {
        discard_line();
        return 0;
    }

    printf("成绩（0-100）：");
    if (scanf("%lf", &new_student.score) != 1) {
        discard_line();
        return 0;
    }

    if (new_student.score < 0.0 || new_student.score > 100.0) {
        return 0;
    }

    students[*count] = new_student;
    (*count)++;
    return 1;
}

void print_students(const Student students[], int count) {
    if (count <= 0) {
        printf("当前没有学生记录。\n");
        return;
    }

    printf("\n序号  姓名                 成绩\n");
    for (int i = 0; i < count; i++) {
        printf("%-5d %-20s %.1f\n",
               i + 1, students[i].name, students[i].score);
    }
}

int find_student(const Student students[], int count, const char name[]) {
    for (int i = 0; i < count; i++) {
        if (strcmp(students[i].name, name) == 0) {
            return i;
        }
    }
    return -1;
}

int calculate_statistics(const Student students[], int count,
                         double *average,
                         double *minimum,
                         double *maximum) {
    if (students == NULL || count <= 0 ||
        average == NULL || minimum == NULL || maximum == NULL) {
        return 0;
    }

    double sum = students[0].score;
    *minimum = students[0].score;
    *maximum = students[0].score;

    for (int i = 1; i < count; i++) {
        double score = students[i].score;
        sum += score;

        if (score < *minimum) {
            *minimum = score;
        }
        if (score > *maximum) {
            *maximum = score;
        }
    }

    *average = sum / count;
    return 1;
}

int main(void) {
    Student students[MAX_STUDENTS];
    int count = 0;
    int running = 1;

    while (running) {
        int choice;
        print_menu();

        if (scanf("%d", &choice) != 1) {
            printf("请输入整数菜单编号。\n");
            discard_line();
            continue;
        }

        switch (choice) {
            case 1:
                if (add_student(students, &count)) {
                    printf("添加成功。\n");
                } else {
                    printf("添加失败，请检查容量、姓名和成绩。\n");
                }
                break;

            case 2:
                print_students(students, count);
                break;

            case 3: {
                char name[NAME_CAPACITY];
                printf("请输入要查询的姓名：");

                if (scanf("%19s", name) == 1) {
                    int index = find_student(students, count, name);
                    if (index >= 0) {
                        printf("%s 的成绩是 %.1f。\n",
                               students[index].name,
                               students[index].score);
                    } else {
                        printf("没有找到该学生。\n");
                    }
                } else {
                    discard_line();
                    printf("姓名输入无效。\n");
                }
                break;
            }

            case 4: {
                double average;
                double minimum;
                double maximum;

                if (calculate_statistics(students, count,
                                         &average, &minimum, &maximum)) {
                    printf("平均分：%.2f\n", average);
                    printf("最低分：%.1f\n", minimum);
                    printf("最高分：%.1f\n", maximum);
                } else {
                    printf("当前没有可统计的数据。\n");
                }
                break;
            }

            case 0:
                running = 0;
                break;

            default:
                printf("没有这个菜单选项。\n");
                break;
        }
    }

    printf("程序已退出。\n");
    return 0;
}
```

## 八、理解基础版本的数据流

添加功能的数据流为：

```text
用户输入 -> 临时 Student 变量 -> 验证 -> 复制到数组 -> count 增加
```

使用临时变量的好处是：只有姓名和成绩全部验证成功后，才修改正式数组。如果读取一半失败，不会留下不完整记录。

统计功能的数据流为：

```text
只读学生数组 -> 遍历成绩 -> 输出参数返回平均、最低、最高 -> 主流程显示
```

计算函数不负责菜单和输入，因此可以独立测试。

## 九、输入处理为什么需要单独设计

`scanf` 读取失败时，错误字符可能仍留在输入流中。如果循环立即再次调用同一格式，可能反复失败。

示例中的 `discard_line` 会读取到换行或文件末尾，用于放弃当前输入行：

```c
void discard_line(void) {
    int ch;
    while ((ch = getchar()) != '\n' && ch != EOF) {
    }
}
```

更复杂的交互程序可以统一采用 `fgets` 读取整行，再使用 `sscanf` 或转换函数解析。不要在项目中随意混用多套输入策略，否则换行和残留字符问题会变得难以预测。

## 十、设计返回值表达成功与失败

`add_student` 返回 1 或 0：

```c
if (add_student(students, &count)) {
    printf("添加成功\n");
} else {
    printf("添加失败\n");
}
```

随着项目扩大，单个布尔结果可能不够。可以定义枚举：

```c
typedef enum AddResult {
    ADD_OK,
    ADD_FULL,
    ADD_INVALID_NAME,
    ADD_INVALID_SCORE
} AddResult;
```

调用者就能针对不同失败原因显示准确消息。函数接口应让调用者能够知道操作是否成功，而不是只在函数内部打印一句话。

## 十一、添加文件保存功能

可以设计文本格式：

```text
Li_Ming 92.5
Wang_Hua 88.0
```

保存函数：

```c
int save_students(const char filename[],
                  const Student students[], int count) {
    FILE *file = fopen(filename, "w");
    if (file == NULL) {
        return 0;
    }

    for (int i = 0; i < count; i++) {
        if (fprintf(file, "%s %.17g\n",
                    students[i].name,
                    students[i].score) < 0) {
            fclose(file);
            return 0;
        }
    }

    return fclose(file) == 0;
}
```

加载时应检查：

- 文件是否成功打开；
- 每条记录是否完整；
- 成绩范围是否有效；
- 数组是否达到容量；
- 遇到损坏记录时是停止、跳过还是整体失败。

这些都是文件格式和需求的一部分，不能等到编码后再临时决定。

## 十二、避免全局可变数据

可以把 `students` 和 `count` 定义为全局变量，但这样每个函数都可能暗中修改它们，不容易看出数据流。

把数组和数量作为参数传递：

```c
print_students(students, count);
add_student(students, &count);
```

函数声明直接说明它需要哪些数据、可能修改什么。对小型项目而言，这种显式参数通常比可修改全局变量更容易测试和维护。

## 十三、何时拆成多个文件

当单文件功能已经正确，并且出现清楚模块边界时，可以拆分：

```text
student.h   Student 类型与公共函数声明
student.c   添加、查询、统计、保存和加载实现
input.h     输入辅助函数声明
input.c     整行读取和数值解析
main.c      菜单和总体流程
```

不要为了“看起来像项目”过早创建大量只有一两个函数的文件。拆分标准应是职责和依赖是否清楚。

## 十四、建议的头文件接口

```c
#ifndef SCORE_MANAGER_STUDENT_H
#define SCORE_MANAGER_STUDENT_H

#include <stddef.h>

#define STUDENT_NAME_CAPACITY 20

typedef struct Student {
    char name[STUDENT_NAME_CAPACITY];
    double score;
} Student;

int student_find(const Student students[], size_t count,
                 const char name[]);
int student_statistics(const Student students[], size_t count,
                       double *average,
                       double *minimum,
                       double *maximum);
int student_save(const char filename[],
                 const Student students[], size_t count);

#endif
```

接口使用模块前缀，减少与其他函数重名。只读数组参数使用 `const`，数量使用 `size_t`，输出结果通过指针返回。

## 十五、测试计划

### 添加学生

- 添加第一名学生；
- 添加到最大容量；
- 容量已满后继续添加；
- 成绩为 0 和 100；
- 成绩小于 0 或大于 100；
- 姓名达到最大允许长度；
- 输入非数字成绩。

### 查询

- 查询第一个和最后一个学生；
- 查询不存在的姓名；
- 空列表查询；
- 若允许重名，明确返回哪一条或全部结果。

### 统计

- 只有一名学生；
- 所有成绩相同；
- 最高分位于首项或末项；
- 空列表；
- 包含 0 分和 100 分。

### 文件

- 文件不存在；
- 空文件；
- 正常多条记录；
- 某行字段缺失；
- 记录超过数组容量；
- 保存路径不可写。

## 十六、使用测试数据而不是只靠手工输入

计算函数可以直接使用固定数据测试：

```c
Student test_data[] = {
    {"A", 80.0},
    {"B", 90.0},
    {"C", 100.0}
};
```

预期平均值是 90，最低分是 80，最高分是 100。固定测试能够重复运行，修改代码后也容易回归验证。

交互流程仍需人工测试，但核心计算逻辑应尽可能脱离输入界面独立验证。

## 十七、常见设计问题

### 1. 一个函数完成所有工作

几百行 `main` 会把输入、计算、文件和显示混在一起。应按职责提取函数。

### 2. 函数划分过碎

每条语句都单独成函数同样会增加跳转和参数负担。函数应代表有名称、可独立说明的任务。

### 3. 数据结构与需求不匹配

若程序需要频繁按学生整体排序，三个平行数组不如结构体数组清楚。

### 4. 只处理正常输入

容量、范围、空数据、格式错误和文件失败都属于需求的一部分。

### 5. 边写边改文件格式

保存与加载必须遵循同一格式。应先写出记录示例和字段规则。

### 6. 过早优化

在 100 条记录的小程序中，清楚正确的线性查找通常比复杂索引更适合。先保证行为正确，再根据实际测量决定优化。

### 7. 复制粘贴重复逻辑

多处出现相同成绩范围判断时，应提取 `is_valid_score` 等函数，避免以后只修改其中一处。

## 十八、代码质量检查表

### 正确性

- 所有输入和函数返回值是否检查；
- 数组下标是否在有效范围；
- 计数与容量是否分清；
- 空数据是否会除零；
- 文件和动态内存是否正确释放。

### 可读性

- 名称是否说明用途；
- 函数是否职责单一；
- 常量是否集中定义；
- 注释是否解释原因和约束，而不是重复代码；
- 是否启用警告并处理诊断。

### 可测试性

- 计算是否能用固定数据独立调用；
- 是否有边界和错误测试；
- 修复后是否重新运行旧测试；
- 文件测试是否包含损坏数据。

## 十九、编译与验证

单文件版本可以使用：

```text
gcc score_manager.c -std=c11 -Wall -Wextra -Wpedantic -o score_manager
```

调试版本可加入：

```text
gcc score_manager.c -std=c11 -Wall -Wextra -Wpedantic \
    -g -O0 -o score_manager
```

多文件版本应把所有实现源文件加入：

```text
gcc main.c student.c input.c -std=c11 \
    -Wall -Wextra -Wpedantic -o score_manager
```

编译通过只是第一步，还要运行测试计划并核对预期结果。

## 二十、进一步扩展方向

基础版本稳定后，可以逐项增加：

- 修改或删除学生；
- 按成绩排序；
- 支持含空格姓名；
- 防止姓名重复；
- 自动保存与加载；
- 为每名学生增加学号；
- 使用动态数组突破固定容量；
- 把错误结果改为枚举；
- 增加课程与多科成绩结构。

每次只增加一个明确功能，并同步更新数据结构、函数接口、文件格式和测试用例。

## 二十一、与整个知识图谱的联系

- 变量、类型和表达式用于表示与计算数据；
- 条件和循环组织菜单与遍历流程；
- 函数把任务拆成可复用、可测试的单元；
- 数组与字符串保存多条记录和文本；
- 指针实现输出参数和数组传递；
- 结构体把同一对象的属性组合起来；
- 枚举表达状态和错误结果；
- 头文件与源文件建立模块边界；
- 文件读写实现数据持久化；
- 调试和未定义行为知识保证程序可靠。

小型程序设计不是独立于前面知识的新语法，而是把这些节点组织成完整解决方案。

## 分层练习

1. 写出成绩管理程序的功能需求、数据约束和至少 10 个测试用例。
2. 先用固定数组完成列表和统计，不加入菜单与文件。
3. 加入添加和查询功能，并验证容量与输入范围。
4. 设计文本文件格式，实现保存和加载，处理损坏记录。
5. 把单文件程序拆成至少两个模块，确保头文件自包含并通过多文件编译。

## 小结

小型程序设计应从需求和约束出发，先选择合适的数据结构，再设计职责清楚的函数。实现过程采用可运行的小步迭代，每一步都处理失败情况并执行测试。程序规模增加后，再按稳定的接口拆分模块。完成项目的标准不是“代码写完了”，而是功能可验证、边界有处理、结构能继续维护。

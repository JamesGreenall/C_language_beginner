# C44. 常见未定义行为

## 节点定位

- 所属模块：文件、调试与综合应用
- 学习难度：综合应用
- 建议学习时间：40-60 分钟
- 典型用途：在 C 程序中正确理解和使用“常见未定义行为”。

## 学习目标

- 能说清楚“常见未定义行为”解决的具体问题。
- 能在一段 C 代码中识别与“常见未定义行为”有关的语法现象。
- 能独立写出一个包含该知识点的最小示例程序。
- 能说明它与前置知识点、后续知识点之间的关系。

## 初学者导读

未定义行为是 C 标准没有规定结果的错误写法。它可能表现为正常运行、结果错误或程序崩溃，因此需要在编码阶段主动避免。

## 关键术语说明

- 未定义行为：C 标准不保证结果的错误写法。
- 野指针：指向未知或无效位置的指针。
- 越界访问：访问数组范围外的位置。
- 整数溢出：数值超过类型能表示的范围。
- 不可预测：不同电脑、不同编译器可能表现不同。

2. 观察它在代码中的基本形式。
3. 分析它会如何影响程序的输入、输出、内存或执行顺序。
4. 理解它与前置知识点和后续知识点的联系。

## 核心概念

未定义行为是 C 标准没有规定结果的行为，程序可能看似正常，也可能崩溃或产生不可预测结果。

## 关键内容

- 数组越界。
- 解引用空指针或野指针。
- 使用未初始化变量。
- 有符号整数溢出。
- `free` 后继续访问内存。
- 返回局部变量地址。

## 示例

```c
int arr[3] = {1, 2, 3};
printf("%d\n", arr[5]); // 未定义行为
```

## 代码逐行解释

- `int arr[3]` 只有下标 0、1、2。
- `arr[5]` 访问了不存在的位置。
- C 语言不保证这种错误一定立刻报错。
- 正确做法是访问前保证下标在合法范围内。

## 常见错误

- 认为“能运行一次”就说明代码正确。
- 忽视编译器警告。
- 不写边界检查。

## 初学者常见误区

- 未定义行为主要风险在于“不一定立刻错”。
- 不要用“我这里能跑”证明代码正确。
- 编译器警告要认真看，很多警告就是未来的 bug。

## 语法格式

```c
// 危险模式
数组越界访问;
解引用无效指针;
使用未初始化变量;
free 后继续使用;
```

3. 思考：为什么“我的电脑上能运行”不能证明没有未定义行为？

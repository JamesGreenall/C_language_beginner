# C44. 常见未定义行为

## 节点定位

- 所属模块：文件、调试与综合应用
- 学习难度：综合应用
- 建议学习时间：120-150 分钟
- 典型用途：识别 C 标准不保证结果的危险写法，避免程序在不同环境或优化级别下出现不可预测问题。

## 学习目标

- 理解未定义行为的准确含义及其危险性。
- 区分未定义行为、未指定行为、实现定义行为和普通逻辑错误。
- 能识别数组越界、无效指针、对象生命周期结束和重复释放。
- 能识别有符号整数溢出、整数除零和错误移位。
- 能识别格式说明符不匹配、未初始化读取和求值顺序问题。
- 建立边界检查、初始化、返回值检查和编译警告等预防习惯。

## 一、什么是未定义行为

未定义行为是指 C 标准对某种程序行为不提出结果要求。发生后，标准不保证程序：

- 一定报错；
- 一定崩溃；
- 一定得到某个错误值；
- 每次运行表现相同；
- 换编译器或开启优化后仍保持原表现。

程序可能看似正常，也可能输出错误、破坏其他数据、崩溃，甚至让后续代码表现得难以解释。

“我的计算机上运行成功”不能证明没有未定义行为，因为一次偶然结果不构成语言规则保证。

## 二、为什么编译器不一定阻止它

C 语言强调效率和对底层资源的直接控制。很多边界与生命周期信息不在运行时自动保存，编译器也无法在编译阶段证明所有地址和下标是否有效。

此外，编译器进行优化时可以假设程序没有触发未定义行为。例如，如果有符号整数溢出按标准不应发生，优化器可能基于“不溢出”推导条件。这就是某些错误代码在 `-O0` 看似正常，开启 `-O2` 后结果变化的原因之一。

## 三、与其他行为类别的区别

### 1. 未定义行为

C 标准不规定结果，例如访问数组边界之外。程序不能依赖任何具体表现。

### 2. 实现定义行为

标准允许不同实现选择结果，但实现必须说明选择。例如普通 `char` 是有符号还是无符号，可能由编译器和平台决定。可移植程序应查阅实现文档或避免依赖差异。

### 3. 未指定行为

标准允许多种结果，但实现不必固定或记录选择。例如某些表达式中函数参数的求值先后顺序未指定。程序不应依赖其中某一种顺序。

### 4. 逻辑错误

程序完全符合语言规则，但算法不符合需求。例如应计算平均值却错误地除以 `count - 1`。结果错误，但不一定属于未定义行为。

区分这些概念有助于判断问题是“规则没有保证”还是“算法写错”。

## 四、数组越界

```c
int values[3] = {10, 20, 30};
printf("%d\n", values[3]);  // 未定义行为
```

合法下标只有 0、1、2。`values[3]` 位于尾后位置，可以形成对应指针用于比较，但不能读取或写入。

正确做法：

```c
if (index >= 0 && index < length) {
    printf("%d\n", values[index]);
}
```

写越界往往比读越界更危险，因为它可能破坏其他变量、返回地址或内存管理信息。

## 五、缓冲区溢出与字符串越界

```c
char name[5];
strcpy(name, "student");  // 目标空间不足
```

字符串 `"student"` 包含 7 个可见字符，还需要一个结尾空字符 `\0`，因此总共需要 8 个字节。`name[5]` 无法容纳，写入会越界。

输入也要限制长度：

```c
char name[20];
scanf("%19s", name);
```

使用 `fgets(name, sizeof name, stdin)` 可以按容量读取，但还要处理长行和保留的换行符。

## 六、解引用空指针

```c
int *p = NULL;
printf("%d\n", *p);  // 未定义行为
```

空指针明确表示不指向有效对象，不能解引用。使用指针参数或动态内存前应检查其是否有效。

仅判断非空仍不保证绝对有效，因为指针还可能悬空、越界或指向生命周期已结束的对象。

## 七、使用未初始化指针

```c
int *p;
*p = 10;  // 未定义行为
```

自动存储期的局部指针若未初始化，会保存不确定表示。程序不知道它指向哪里。

应初始化为有效对象地址或空指针：

```c
int value = 0;
int *p = &value;

int *q = NULL;
```

## 八、使用生命周期已结束的地址

```c
int *wrong(void) {
    int value = 10;
    return &value;
}
```

函数返回后，局部变量 `value` 的生命周期结束。返回的地址变成悬空地址，不能继续解引用。

即使该内存位置暂时仍保留数字 10，也不再属于那个对象。后续函数调用或优化可能立刻改变表现。

## 九、释放后继续使用

```c
int *data = malloc(5 * sizeof *data);
if (data != NULL) {
    data[0] = 10;
    free(data);
    printf("%d\n", data[0]);  // 未定义行为
}
```

`free` 后动态对象生命周期结束。旧指针仍可能保存地址数值，但没有访问权。

释放后置空可以减少当前指针误用：

```c
free(data);
data = NULL;
```

若还有其他指针指向同一空间，它们仍会悬空，所以根本解决办法是明确所有权和使用期限。

## 十、重复释放与错误释放

```c
free(data);
free(data);  // 未定义行为
```

同一动态块只能释放一次。还不能释放：

- 普通局部变量地址；
- 普通数组地址；
- 字符串字面量地址；
- 动态块中间某个元素的地址；
- 已经释放的地址。

`free(NULL)` 是允许的，不执行任何操作。

## 十一、读取未初始化的自动变量

```c
int total;
printf("%d\n", total);
```

局部自动变量没有自动获得 0。读取不确定值可能导致未定义行为或其他不可依赖结果。

应在首次读取前明确赋值：

```c
int total = 0;
```

编译器警告“may be used uninitialized”时应认真检查所有控制流路径。

## 十二、有符号整数溢出

```c
#include <limits.h>

int value = INT_MAX;
value = value + 1;  // 未定义行为
```

有符号整数运算结果超出类型范围会产生未定义行为。不能可靠地假设一定绕回 `INT_MIN`。

运算前可检查：

```c
if (value <= INT_MAX - amount) {
    value += amount;
} else {
    printf("结果超出 int 范围\n");
}
```

无符号整数溢出不同：它按模运算回绕，是标准定义的行为。但如果算法不希望回绕，仍然属于需要检查的逻辑风险。

## 十三、乘法计算大小时溢出

```c
int *data = malloc(count * sizeof *data);
```

若 `count` 很大，乘法可能回绕成较小字节数，随后按原 `count` 写入就会越界。应使用 `size_t` 并先检查：

```c
#include <stdint.h>

if (count > SIZE_MAX / sizeof *data) {
    printf("申请规模过大\n");
    return 1;
}
```

此外还要验证由用户输入转换得到的 `count` 是否合理。

## 十四、整数除零和特殊溢出

```c
int result = value / 0;  // 未定义行为
```

除数来自变量时也必须检查：

```c
if (divisor != 0) {
    result = dividend / divisor;
}
```

对有符号整数，还要注意最小值除以 -1。例如在二进制补码常见环境中，`INT_MIN / -1` 的数学结果可能超出 `int` 最大值，同样会产生未定义行为。

## 十五、错误的移位操作

```c
int value = 1 << 32;  // 若 int 只有 32 位，移位次数无效
```

移位次数为负数，或大于等于左操作数类型的位宽，会产生未定义行为。对有符号数左移还存在结果可表示性等限制。

处理位数据时通常使用无符号类型，并确保移位次数处于合法范围：

```c
if (shift >= 0 && (unsigned int)shift < sizeof value * CHAR_BIT) {
    value <<= shift;
}
```

这里需要包含 `<limits.h>` 以使用 `CHAR_BIT`。

## 十六、格式说明符与参数类型不匹配

```c
long value = 1000;
printf("%d\n", value);  // 类型不匹配，行为未定义
```

可变参数函数无法通过普通函数形参完整校正所有类型。格式字符串必须与实际参数匹配：

```c
printf("%ld\n", value);
```

常见对应关系：

| 类型 | printf | scanf |
| --- | --- | --- |
| `int` | `%d` | `%d` 与 `int *` |
| `long` | `%ld` | `%ld` 与 `long *` |
| `double` | `%f` | `%lf` 与 `double *` |
| `size_t` | `%zu` | `%zu` 与 `size_t *` |
| 地址 | `%p` 与 `void *` | 通常不用于初学输入 |

启用格式警告能够发现许多此类问题。

## 十七、scanf 地址或类型错误

```c
int age;
scanf("%d", age);  // 错误：没有传入 int *
```

`scanf` 会把结果写入给定地址，应传入：

```c
scanf("%d", &age);
```

格式与目标类型也必须一致。把 `double *` 配给 `%f` 或把 `int *` 配给 `%ld` 都会让函数按错误方式写内存。

## 十八、修改字符串字面量

```c
char *text = "hello";
text[0] = 'H';  // 未定义行为
```

字符串字面量不允许通过指针修改。若需要可修改字符数组，应写：

```c
char text[] = "hello";
text[0] = 'H';
```

前者是指针指向字符串字面量，后者创建并初始化可修改数组。

## 十九、同一完整表达式中的无序修改

```c
int i = 1;
i = i++ + 1;  // 未定义行为
```

一个变量的修改与其他读取或修改之间若没有适当的求值顺序约束，可能产生未定义行为。宏参数重复展开也容易制造类似问题：

```c
#define SQUARE(x) ((x) * (x))
int result = SQUARE(i++);  // 危险
```

不要编写依赖复杂求值顺序的表达式。拆成多条简单语句：

```c
int old = i;
i++;
int result = old * old;
```

## 二十、重叠内存使用错误函数

`memcpy` 要求源区域与目标区域不重叠：

```c
memcpy(buffer + 1, buffer, 5);  // 若区域重叠，行为未定义
```

重叠复制应使用 `memmove`：

```c
memmove(buffer + 1, buffer, 5);
```

这属于较进阶的内存操作，但体现了一个重要原则：使用标准函数前必须满足其参数约定。

## 二十一、错误的库函数参数

许多标准函数要求指针有效并指向足够空间。例如：

```c
printf("%s\n", NULL);  // 标准不保证可用
strlen(NULL);           // 无效指针
fclose(NULL);           // 不是有效文件流
```

某些系统可能对个别情况输出特殊文字，但不能依赖扩展行为。调用前应满足函数文档规定的前置条件。

## 二十二、未定义行为会“传播”

一旦程序执行到未定义行为，不能只把该表达式结果视为随机数并假设后续仍按规则执行。编译器可能已经基于“该情况不会发生”重排或删除代码。

因此调试时不能问“越界后下一行应该得到什么”，而应先消除越界，再讨论后续行为。

## 二十三、如何系统预防

### 编写阶段

- 所有局部变量在读取前初始化；
- 数组访问同时携带长度并检查边界；
- 指针解引用前确认来源、生命周期和范围；
- 动态内存明确所有权并只释放一次；
- 检查除数、移位次数和算术范围；
- 格式字符串与参数类型逐一对应；
- 复杂表达式拆成多条简单语句。

### 编译阶段

```text
gcc main.c -std=c11 -Wall -Wextra -Wpedantic -o main
```

认真处理每条警告。

### 测试阶段

- 测试空输入、最小和最大容量；
- 测试首尾下标；
- 使用地址和未定义行为检测工具；
- 在不同优化级别下测试，但不要把表现一致当成正确证明。

## 二十四、危险与安全写法对照

| 危险写法 | 问题 | 较安全思路 |
| --- | --- | --- |
| `arr[length]` | 越界 | 保证 `index < length` |
| `*p`，但来源不明 | 无效解引用 | 初始化并验证生命周期 |
| `free(p); *p = 1;` | 释放后使用 | 释放后停止访问并置空 |
| `INT_MAX + 1` | 有符号溢出 | 运算前检查范围 |
| `a / b` | `b` 可能为 0 | 先验证除数 |
| `printf("%d", value)` | 格式可能不匹配 | 按真实类型选择格式 |
| `SQUARE(i++)` | 参数重复求值 | 先保存临时值 |

## 二十五、与相关知识的联系

- C06 基本数据类型：类型范围决定溢出和格式选择。
- C27 数组：有效下标和尾后位置是避免越界的基础。
- C31 地址与内存：地址必须对应仍然存在且允许访问的对象。
- C32 指针基础：空指针、未初始化指针和悬空指针都不能解引用。
- C35 动态内存：释放后使用、重复释放和大小计算错误都很危险。
- C40 宏定义：参数重复求值可能引入无序修改。
- C43 错误与调试：警告、断言和运行时检测可以帮助发现部分未定义行为。

## 分层练习

1. 列出数组访问、指针使用和整数运算各两种未定义行为，不运行危险代码。
2. 修正一个包含未初始化累计值和 `i <= length` 的求和函数。
3. 为整数加法、除法和移位分别编写输入范围检查。
4. 检查一组 `printf/scanf` 调用，逐项确认格式与参数类型。
5. 解释为什么程序在关闭优化时正常、开启优化后异常，仍可能是源代码未定义行为，而不是编译器错误。

## 小结

未定义行为意味着 C 标准不保证任何结果，不能把一次成功运行当成正确证据。多数风险来自越界、无效生命周期、错误类型、算术超范围和复杂求值。可靠代码通过初始化、边界检查、明确所有权、正确格式、编译警告和运行时检测主动预防，而不是等待程序崩溃后再修补。

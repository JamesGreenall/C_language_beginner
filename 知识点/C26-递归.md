# C26. 递归

## 节点定位

- 所属模块：函数与模块化
- 学习难度：基础
- 建议学习时间：30-40 分钟
- 典型用途：用函数调用自身的方式解决可分解为同类小问题的问题。

## 学习目标

- 能说明递归是什么。
- 能识别递归函数中的终止条件和递归调用。
- 能理解递归每一层调用都有自己的参数和局部变量。
- 能手算简单递归函数的执行过程。
- 能说明递归为什么可能造成栈溢出。
- 能判断简单问题适合用递归还是循环。

## 初学者导读

递归是函数调用自己的一种写法。它看起来比较特殊，但本质仍然是函数调用。

例如，计算 5 的阶乘可以这样想：

```text
5! = 5 * 4!
4! = 4 * 3!
3! = 3 * 2!
2! = 2 * 1!
1! = 1
```

可以发现，大问题 `5!` 被拆成了形式相同、规模更小的问题 `4!`。这种“用同样方法解决更小问题”的结构，很适合用递归表达。

学习递归时，不要把它看成神秘技巧。递归只是在函数执行过程中，又调用了同一个函数。重点是：什么时候停止，以及每次调用是否离停止更近。

## 关键术语说明

- 递归：函数直接或间接调用自身。
- 递归函数：包含递归调用的函数。
- 递归调用：函数内部再次调用同一个函数。
- 终止条件：让递归停止继续调用的条件。
- 基本情况：不需要继续拆分、可以直接得到结果的情况。
- 递归步骤：把当前问题转化为更小的同类问题。
- 问题规模：问题的大小，例如 `n`、数组长度、剩余元素个数。
- 调用栈：程序记录函数调用过程的数据结构。
- 栈溢出：递归层数太深，调用栈空间不足导致的错误。

## 学习思路

学习递归时，建议按照以下顺序：

1. 先找出最简单、可以直接回答的情况。
2. 再找出如何把当前问题变成更小的同类问题。
3. 确认每次递归调用都更接近终止条件。
4. 用小数据手算调用和返回过程。

如果不能说清楚终止条件，就不要急着写递归代码。

## 核心概念

递归函数通常包含两部分：

```c
返回类型 函数名(问题规模) {
    if (终止条件) {
        return 基本结果;
    }

    return 当前步骤与函数名(更小问题规模)的组合;
}
```

以阶乘为例：

```c
int factorial(int n) {
    if (n <= 1) {
        return 1;
    }

    return n * factorial(n - 1);
}
```

这里：

- `n <= 1` 是终止条件。
- `return 1;` 是基本结果。
- `factorial(n - 1)` 是递归调用。
- `n - 1` 让问题规模变小。

## 递归的两个必要条件

### 1. 必须有终止条件

终止条件用于阻止函数无限调用自己。

```c
if (n <= 1) {
    return 1;
}
```

如果没有终止条件，函数会一直调用自己，直到程序出错。

### 2. 每次调用都要接近终止条件

下面写法是合理的：

```c
factorial(n - 1)
```

因为 `n` 每次减少 1，最终会到达 `n <= 1`。

错误示例：

```c
int factorial(int n) {
    if (n <= 1) {
        return 1;
    }

    return n * factorial(n);
}
```

这里每次仍然调用 `factorial(n)`，问题规模没有变小，递归不会停止。

## 手算 factorial(4)

调用：

```c
factorial(4)
```

展开过程：

```text
factorial(4)
= 4 * factorial(3)
= 4 * (3 * factorial(2))
= 4 * (3 * (2 * factorial(1)))
= 4 * (3 * (2 * 1))
= 24
```

也可以分成“调用阶段”和“返回阶段”。

调用阶段：

```text
factorial(4) 等待 factorial(3)
factorial(3) 等待 factorial(2)
factorial(2) 等待 factorial(1)
factorial(1) 返回 1
```

返回阶段：

```text
factorial(2) 返回 2 * 1 = 2
factorial(3) 返回 3 * 2 = 6
factorial(4) 返回 4 * 6 = 24
```

递归不是一下子得到结果，而是一层层调用，再一层层返回。

## 每一层调用都有自己的变量

递归调用时，每一层函数调用都有自己的参数和局部变量。

```c
int factorial(int n) {
    if (n <= 1) {
        return 1;
    }

    return n * factorial(n - 1);
}
```

在 `factorial(4)`、`factorial(3)`、`factorial(2)` 中，虽然参数都叫 `n`，但它们属于不同调用层。

可以理解为：

| 调用层 | 本层 `n` 的值 |
|---|---|
| `factorial(4)` | 4 |
| `factorial(3)` | 3 |
| `factorial(2)` | 2 |
| `factorial(1)` | 1 |

这些 `n` 不是同一个变量，只是名字相同。

## 调用栈的直观理解

程序需要记住每一层函数调用还没有完成的事情。例如：

```text
factorial(4) 还要乘 4
factorial(3) 还要乘 3
factorial(2) 还要乘 2
factorial(1) 返回 1
```

这些“尚未完成的调用信息”会放在调用栈中。

如果递归太深，调用栈会占用很多内存，最终可能栈溢出。

例如：

```c
int f(int n) {
    return f(n + 1);
}
```

这个函数没有终止条件，会不断调用自己，最终导致程序错误。

## 递归求和

计算 `1 + 2 + ... + n` 也可以用递归。

```c
int sum_to_n(int n) {
    if (n <= 1) {
        return n;
    }

    return n + sum_to_n(n - 1);
}
```

例如：

```text
sum_to_n(4)
= 4 + sum_to_n(3)
= 4 + 3 + sum_to_n(2)
= 4 + 3 + 2 + sum_to_n(1)
= 4 + 3 + 2 + 1
= 10
```

这里的终止条件是 `n <= 1`，递归步骤是 `sum_to_n(n - 1)`。

## 递归与循环的关系

有些问题既能用递归，也能用循环。

递归版阶乘：

```c
int factorial(int n) {
    if (n <= 1) {
        return 1;
    }

    return n * factorial(n - 1);
}
```

循环版阶乘：

```c
int factorial_loop(int n) {
    int result = 1;

    for (int i = 1; i <= n; i++) {
        result = result * i;
    }

    return result;
}
```

循环版通常更节省栈空间，也更容易控制执行次数。递归版在问题天然具有“拆成同类子问题”的结构时更清楚。

初学阶段不要把递归当成必须使用的写法。能够用循环清楚解决的问题，用循环也很好。

## 递归适合什么问题

递归适合满足以下特点的问题：

- 可以拆成规模更小的同类问题。
- 存在明确的最小情况。
- 大问题的答案可以由小问题的答案组合得到。

典型例子：

- 阶乘。
- 递归求和。
- 斐波那契数列。
- 后续学习中的树形结构。

但有些递归写法效率较低，例如朴素斐波那契递归会重复计算很多次。初学阶段可以用它理解递归思想，但不一定适合实际高效程序。

## 示例

```c
#include <stdio.h>

int factorial(int n) {
    if (n <= 1) {
        return 1;
    }

    return n * factorial(n - 1);
}

int main(void) {
    int n;
    scanf("%d", &n);

    if (n < 0) {
        printf("invalid\n");
    } else {
        printf("%d\n", factorial(n));
    }

    return 0;
}
```

## 代码逐行解释

- `int factorial(int n)`：定义递归函数，计算 `n` 的阶乘。
- `if (n <= 1)`：终止条件，0 和 1 的阶乘都返回 1。
- `return n * factorial(n - 1);`：把问题拆成 `n` 乘以更小的阶乘。
- `scanf("%d", &n);`：输入要计算的整数。
- `if (n < 0)`：阶乘通常只讨论非负整数，负数输入视为无效。
- `factorial(n)`：调用递归函数并输出结果。

## 常见错误

- 没有终止条件，导致无限递归。
- 递归调用没有让问题规模变小。
- 终止条件写错，导致多算、少算或无法停止。
- 不理解每一层调用都有独立参数和局部变量。
- 对很大的输入使用递归，导致栈溢出。
- 把能简单用循环解决的问题强行写成复杂递归。

## 初学者常见误区

- 递归不是特殊魔法，只是函数调用自己。
- 写递归前应先找终止条件。
- 每次递归调用都必须更接近终止条件。
- 递归函数的返回过程和调用过程方向相反。
- 同名参数在不同调用层中不是同一个变量。
- 递归可能比循环更耗费栈空间。

## 语法格式

```c
返回类型 函数名(问题规模) {
    if (终止条件) {
        return 基本结果;
    }

    return 当前处理 + 函数名(更小的问题规模);
}
```

常见模式：

```c
int f(int n) {
    if (n <= 终止值) {
        return 基本结果;
    }

    return 组合当前值和 f(n - 1);
}
```

## 练习题

1. 手算 `factorial(4)` 的调用过程和返回过程。
2. 写递归函数计算 `1 + 2 + ... + n`。
3. 故意去掉递归终止条件，观察程序会出现什么问题。
4. 说明为什么 `factorial(n)` 中要调用 `factorial(n - 1)`，而不是 `factorial(n)`。
5. 写出递归函数必须具备的两个条件。

## 分层练习

1. 基础：手算 `sum_to_n(3)`。
2. 基础：写递归函数输出从 `n` 到 1。
3. 提升：写递归函数计算整数的各位数字之和。
4. 提升：把递归阶乘改写成循环阶乘。
5. 进阶：阅读斐波那契递归代码，指出它的终止条件和递归调用。
6. 思考：递归写法什么时候更清楚？什么时候循环更合适？

## 小结

递归是函数调用自身的程序设计方式。它适合解决能拆分为同类小问题的问题。学习递归时，最重要的是终止条件和问题规模缩小。只要能手算小规模调用过程，就能逐步理解递归的执行方式。

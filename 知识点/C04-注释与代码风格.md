# C04. 注释与代码风格

## 节点定位

- 所属模块：程序结构与开发基础
- 学习难度：入门
- 建议学习时间：20-30 分钟
- 典型用途：在 C 程序中正确理解和使用“注释与代码风格”。

## 学习目标

- 能说清楚“注释与代码风格”解决的具体问题。
- 能在一段 C 代码中识别与“注释与代码风格”有关的语法现象。
- 能独立写出一个包含该知识点的最小示例程序。
- 能说明它与前置知识点、后续知识点之间的关系。

## 初学者导读

注释和代码风格服务于代码的可读性。对于初学者来说，规范的命名、缩进和必要说明，可以降低阅读、修改和调试程序的难度。

## 关键术语说明

- 注释：给人看的解释，编译时会被忽略。
- 代码风格：缩进、命名、空行等约定。
- 可读性：别人能不能轻松看懂你的代码。
- 维护：以后修改、扩展、排错。
- 意图：你为什么这样写，而不只是写了什么。

## 学习思路

学习本知识点时，建议按照以下顺序理解：

1. 明确它要解决的具体问题。
2. 观察它在代码中的基本形式。
3. 分析它会如何影响程序的输入、输出、内存或执行顺序。
4. 理解它与前置知识点和后续知识点的联系。

## 核心概念

注释用于解释代码意图，代码风格用于提升可读性。好的 C 程序不仅要能运行，还要方便别人维护。

## 关键内容

- 单行注释：`// comment`
- 多行注释：`/* comment */`
- 命名要表达含义。
- 缩进要统一。
- 一段代码只做一件清晰的事情。

## 示例

```c
// Calculate the area of a rectangle.
int area = width * height;
```

## 代码逐行解释

- `//` 后面的内容只解释这一行。
- `/* ... */` 可以写多行说明。
- 示例中的注释解释了下一行计算矩形面积的目的。
- `width * height` 才是真正被电脑执行的表达式，注释不会参与计算。

## 常见错误

- 注释描述“代码做了什么”，但没有说明“为什么这样做”。
- 注释与代码不一致。
- 命名过短，如 `a`、`b`、`x1`，导致含义不清。

## 初学者常见误区

- 注释不是越多越好，关键是解释不明显的意图。
- 代码改了，注释也要跟着改。
- 风格统一比个人花样更重要。

## 语法格式

```c
// 单行注释

/*
   多行注释
*/
```

## 练习题

1. 用 3-5 句话解释“注释与代码风格”的作用，并写出一个最小代码片段。
2. 修改本文示例代码，加入一个新的输入、判断或输出，让程序行为发生可观察变化。
3. 人为制造一个本文“常见错误”中的问题，记录编译器提示或运行结果，再修正它。

## 分层练习

1. 基础：给一个计算面积的小程序添加 3 条有意义的注释。
2. 提升：把变量名从 `a`、`b` 改成 `width`、`height`。
3. 思考：哪些代码不需要注释？哪些代码最好写注释？

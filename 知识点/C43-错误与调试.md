# C43. 错误与调试

## 节点定位

- 所属模块：文件、调试与综合应用
- 学习难度：综合应用
- 建议学习时间：40-60 分钟
- 典型用途：在 C 程序中正确理解和使用“错误与调试”。

## 学习目标

- 能说清楚“错误与调试”解决的具体问题。
- 能在一段 C 代码中识别与“错误与调试”有关的语法现象。
- 能独立写出一个包含该知识点的最小示例程序。
- 能说明它与前置知识点、后续知识点之间的关系。

## 初学者导读

调试是定位和修正程序错误的过程。初学者应学会区分编译错误、运行时错误和逻辑错误，并通过输出信息或调试工具逐步缩小问题范围。

## 关键术语说明

- 编译错误：代码语法或类型不符合规则。
- 链接错误：找不到函数实现或重复定义。
- 运行时错误：程序运行过程中出问题。
- 逻辑错误：程序能跑，但结果不对。
- 最小复现：用最少代码重现问题。

## 学习思路

学习本知识点时，建议按照以下顺序理解：

1. 明确它要解决的具体问题。
2. 观察它在代码中的基本形式。
3. 分析它会如何影响程序的输入、输出、内存或执行顺序。
4. 理解它与前置知识点和后续知识点的联系。

## 核心概念

调试是定位和修复错误的过程。C 程序错误通常分为编译错误、链接错误、运行时错误和逻辑错误。

## 关键内容

- 编译错误：语法不合法。
- 链接错误：找不到函数或重复定义。
- 运行时错误：数组越界、空指针、除零等。
- 逻辑错误：程序能运行但结果不对。
- 常用方法：阅读报错、打印变量、使用调试器、缩小问题范围。

## 示例

```c
printf("debug: x = %d\n", x);
```

## 代码逐行解释

- `printf("debug: x = %d\n", x);`：临时输出变量值。
- 这样可以观察程序运行到某一步时变量是什么。
- 调试输出用完后可以删除或改成更正式的日志。
- 如果输出和你预期不同，就沿着代码往前找原因。

## 常见错误

- 只看第一行报错，忽略真正原因。
- 修改多处代码后再测试，难以定位问题。
- 没有构造边界测试。

## 初学者常见误区

- 报错很多时先看最前面的错误。
- 一次只改一个小问题，再重新运行。
- 调试要靠证据，不要只仅凭猜测。

## 练习题

1. 用 3-5 句话解释“错误与调试”的作用，并写出一个最小代码片段。
2. 修改本文示例代码，加入一个新的输入、判断或输出，让程序行为发生可观察变化。
3. 人为制造一个本文“常见错误”中的问题，记录编译器提示或运行结果，再修正它。

## 分层练习

1. 基础：故意写一个少分号的程序，阅读编译错误。
2. 提升：用 `printf` 输出循环变量，观察循环过程。
3. 思考：遇到结果错误时，怎样一步步缩小问题范围？

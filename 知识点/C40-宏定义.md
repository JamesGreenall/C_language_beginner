# C40. 宏定义

## 节点定位

- 所属模块：预处理与多文件组织
- 学习难度：综合应用
- 建议学习时间：90-120 分钟
- 典型用途：为常量、编译配置和少量通用代码模式建立预处理阶段的替换规则。

## 学习目标

- 理解宏的本质是预处理替换，不是变量或普通函数。
- 会定义和使用对象式宏与函数式宏。
- 理解宏名称、参数和整体表达式为什么需要恰当括号。
- 能识别参数重复求值造成的副作用风险。
- 会在宏、`const` 对象、枚举常量和函数之间作出基本选择。
- 了解 `#` 字符串化、`##` 记号拼接和多语句宏的基本用途。

## 一、宏不是运行时变量

最简单的宏定义如下：

```c
#define MAX_STUDENTS 50
```

预处理器从定义位置开始，根据规则展开后续代码中的 `MAX_STUDENTS`：

```c
int scores[MAX_STUDENTS];
```

可初步理解为形成：

```c
int scores[50];
```

`MAX_STUDENTS` 不是一个变量：

- 不会在运行时占据普通变量空间；
- 没有可以使用 `&MAX_STUDENTS` 获得的变量地址；
- 不接受普通变量那样的类型检查；
- 不能在程序运行时改变替换内容。

宏只是预处理阶段识别的名称和替换规则。

## 二、对象式宏

不带参数的宏称为对象式宏：

```c
#define PI 3.141592653589793
#define BUFFER_SIZE 256
#define APP_NAME "Score Manager"
```

使用方式看起来像常量名称：

```c
double circumference = 2.0 * PI * radius;
char buffer[BUFFER_SIZE];
printf("%s\n", APP_NAME);
```

名称通常使用全大写字母和下划线，以便读者识别它不是普通变量。但这是一种常见命名约定，不是语法强制要求。

## 三、宏定义末尾通常不写分号

错误示例：

```c
#define BUFFER_SIZE 256;
```

分号会成为替换内容的一部分。若写：

```c
int data[BUFFER_SIZE];
```

展开后可能形成不合法代码：

```c
int data[256;];
```

因此宏定义只写需要替换的内容，不要照搬普通语句的分号习惯。

## 四、函数式宏

带参数、使用形式类似函数调用的宏称为函数式宏：

```c
#define SQUARE(x) ((x) * (x))
```

使用：

```c
int result = SQUARE(5);
```

预处理后可理解为：

```c
int result = ((5) * (5));
```

虽然写法类似函数调用，`SQUARE` 并不是真正的 C 函数。预处理器主要按照宏规则替换参数，不进行普通函数调用所具有的参数类型检查。

## 五、宏名与左括号之间不能有空格

定义函数式宏时应写：

```c
#define SQUARE(x) ((x) * (x))
```

若写成：

```c
#define SQUARE (x) ((x) * (x))
```

宏名后的空格使其成为对象式宏，替换内容从 `(x)` 开始。这与预期的函数式宏完全不同。

调用宏时，名称与左括号之间可以有空白，但为了清楚，通常仍写成 `SQUARE(value)`。

## 六、为什么每个宏参数都要加括号

错误定义：

```c
#define SQUARE(x) x * x
```

调用：

```c
int result = SQUARE(2 + 3);
```

简单文本替换后会形成：

```c
int result = 2 + 3 * 2 + 3;
```

乘法优先执行，结果不是预期的 25。

给每次参数使用加括号：

```c
#define SQUARE(x) (x) * (x)
```

展开为：

```c
(2 + 3) * (2 + 3)
```

参数内部的运算顺序得到了保护。

## 七、为什么整个替换表达式也要加括号

只给参数加括号仍然不够：

```c
#define SQUARE(x) (x) * (x)
```

若调用：

```c
int result = 100 / SQUARE(5);
```

展开后是：

```c
int result = 100 / (5) * (5);
```

除法与乘法同级并从左向右计算，结果会变成 100，而不是 4。

正确定义应同时保护参数和整体：

```c
#define SQUARE(x) ((x) * (x))
```

展开后是：

```c
int result = 100 / ((5) * (5));
```

## 八、两个参数的宏

```c
#define MAX(a, b) (((a) > (b)) ? (a) : (b))
```

每个参数出现位置都加括号，整个条件表达式也加括号：

```c
int greater = MAX(x + 1, y * 2);
```

但即使括号完整，宏仍然存在参数重复求值问题，下一节会说明。

## 九、宏参数的副作用风险

副作用是表达式在计算值的同时改变程序状态，例如：

```c
i++
--count
scanf("%d", &value)
```

如果把带副作用的表达式传给重复使用参数的宏：

```c
int i = 3;
int result = SQUARE(i++);
```

宏可能展开为：

```c
int result = ((i++) * (i++));
```

`i++` 被执行两次，而且两个修改之间缺乏可靠的求值顺序，可能产生未定义行为。

同样，下列调用也危险：

```c
int larger = MAX(i++, j++);
```

被选中的参数可能再次求值，最终自增次数并不符合普通函数“一次传参”的直觉。

基本规则是：不要把带副作用的表达式传给可能重复使用参数的宏。先计算到临时变量中再调用：

```c
int value = i++;
int result = SQUARE(value);
```

## 十、宏没有普通函数的类型约束

```c
#define SQUARE(x) ((x) * (x))
```

这个宏可以展开整数、浮点数，甚至某些不适合相乘的表达式。真正是否合法，要到展开后的 C 代码进入编译时才检查。

普通函数则有明确参数和返回类型：

```c
double square(double x) {
    return x * x;
}
```

函数参数只求值一次，调试信息也通常更清晰。因此，能够使用普通函数清楚完成的任务，通常优先使用函数。

## 十一、对象式宏与 const 对象

以下两种写法看起来都表示不应修改的数值：

```c
#define TAX_RATE 0.13

const double tax_rate = 0.13;
```

它们并不完全相同：

| 对比项 | 对象式宏 | `const` 对象 |
| --- | --- | --- |
| 处理阶段 | 预处理 | 编译阶段 |
| 类型 | 宏本身没有普通对象类型 | 有明确类型 |
| 地址 | 不能取得宏对象地址 | 可以取得对象地址 |
| 调试观察 | 可能不直观 | 通常可作为变量观察 |
| 作用域规则 | 由定义位置和 `#undef` 控制 | 遵守 C 语言作用域 |

若需要一个有明确类型的只读数据，通常优先考虑 `const`。若需要在预处理条件中使用，或作为头文件保护标记，则必须使用宏。

## 十二、整数常量还可以考虑枚举

一组相关整数常量可使用枚举：

```c
enum {
    MAX_STUDENTS = 50,
    MAX_COURSES = 10
};
```

枚举常量由编译器理解，适合整数常量。字符串、浮点替换或条件编译标记则不能直接用这种方式替代。

选择时应看用途，而不是把所有常量都机械地写成宏。

## 十三、跨行宏

较长宏可以用反斜杠续行：

```c
#define PRINT_POINT(x, y) \
    printf("point = (%d, %d)\n", (x), (y))
```

反斜杠必须位于该行末尾。若后面存在空格或其他字符，续行可能失效。

跨行宏会增加阅读和调试难度。逻辑稍复杂时，应优先改成函数。

## 十四、多语句宏为什么危险

直接写多个语句：

```c
#define RESET_PAIR(a, b) (a) = 0; (b) = 0
```

放入条件语句后可能破坏结构：

```c
if (ready)
    RESET_PAIR(x, y);
else
    printf("not ready\n");
```

展开后的分号和语句边界可能使 `else` 无法按预期匹配。

传统 C 代码常使用 `do { ... } while (0)` 包装多语句宏：

```c
#define RESET_PAIR(a, b) \
    do {                  \
        (a) = 0;          \
        (b) = 0;          \
    } while (0)
```

这样调用处可以像单条语句一样书写：

```c
RESET_PAIR(x, y);
```

不过，对初学项目而言，写成函数通常更简单、更安全：

```c
void reset_pair(int *a, int *b) {
    *a = 0;
    *b = 0;
}
```

## 十五、# 字符串化运算符

在函数式宏替换列表中，`#` 可以把宏参数转换为字符串字面量：

```c
#define SHOW_NAME(x) printf("%s\n", #x)
```

调用：

```c
SHOW_NAME(student_score);
```

可形成类似：

```c
printf("%s\n", "student_score");
```

字符串化常用于调试工具，让程序同时输出表达式文本和值：

```c
#define SHOW_INT(x) printf(#x " = %d\n", (x))
```

调用 `SHOW_INT(count);` 可以输出变量名称和当前值。仍应避免传入具有副作用的复杂表达式。

## 十六、## 记号拼接运算符

`##` 可以在宏展开时把两个预处理记号拼接成一个：

```c
#define DECLARE_INT(name) int value_##name

DECLARE_INT(first) = 10;
DECLARE_INT(second) = 20;
```

可以形成名称 `value_first` 和 `value_second`。

记号拼接适合少量规则明确的代码生成，但过度使用会制造源文件中无法直接搜索到的标识符，降低可读性。初学阶段理解其作用即可，不建议在普通练习中大量使用。

## 十七、可变参数宏简介

C 语言支持接收可变数量参数的宏：

```c
#define LOG(format, ...) \
    printf("[LOG] " format "\n", __VA_ARGS__)
```

例如：

```c
LOG("score = %d", score);
```

`__VA_ARGS__` 代表省略号位置接收到的参数。不同 C 标准和编译器对“没有额外参数”的处理细节可能不同，因此入门阶段应保持调用形式简单，并优先使用普通日志函数。

## 十八、取消宏定义

```c
#define BUFFER_SIZE 256

/* 使用 BUFFER_SIZE */

#undef BUFFER_SIZE
```

`#undef` 从当前位置起取消宏。它有时用于避免第三方头文件宏冲突，但频繁改变同名宏含义会使代码难以理解。

若宏名称与其他模块冲突，更好的办法通常是使用清晰前缀，例如 `STUDENT_BUFFER_SIZE`。

## 十九、用于日志与断言的宏

宏能够自动插入文件名和行号：

```c
#define LOG_ERROR(message) \
    fprintf(stderr, "%s:%d: %s\n", __FILE__, __LINE__, (message))
```

调用：

```c
LOG_ERROR("invalid score");
```

预定义宏 `__FILE__` 和 `__LINE__` 会在调用位置展开，因此日志能够指出源代码位置。这是宏比普通函数更适合的少数典型场景之一。

标准库 `<assert.h>` 中的 `assert` 也常由宏实现，使其能够记录表达式文本和位置。发布构建中是否启用断言受 `NDEBUG` 宏影响，因此断言不应承担必须执行的业务操作。

## 二十、查看宏展开结果

当宏行为不符合预期时，可以使用 GCC 查看预处理结果：

```text
gcc -E main.c
```

建议先建立一个只包含少量宏的短文件，再观察展开结果。分析顺序可以是：

1. 把实参代入宏参数位置；
2. 检查参数出现了几次；
3. 检查每个参数和整体是否有括号；
4. 按 C 运算符优先级重新分析展开后的表达式；
5. 检查是否包含自增、赋值或函数调用等副作用。

## 二十一、常见错误与原因

### 1. 把宏当成变量

宏不具有普通变量的类型、地址和运行时赋值行为。

### 2. 在替换内容末尾添加不必要的分号

分号会被带到每一个使用位置，可能破坏表达式或声明。

### 3. 参数或整体缺少括号

复杂实参和外层运算会改变展开后的计算顺序。

### 4. 传入带副作用的表达式

参数可能在展开结果中出现多次，导致多次求值甚至未定义行为。

### 5. 宏名与左括号之间出现空格

定义函数式宏时，这会把它变成对象式宏。

### 6. 用宏实现过于复杂的逻辑

宏缺少普通函数的作用域、参数求值和调试体验。逻辑复杂时应使用函数。

### 7. 宏名称过于通用

`MAX`、`ERROR`、`DEBUG` 等名称可能与其他头文件冲突。公共宏应使用模块前缀。

## 二十二、宏、常量与函数的选择

| 需求 | 较合适的工具 |
| --- | --- |
| 条件编译开关 | 宏 |
| 头文件保护 | 宏 |
| 需要文件名和行号的日志 | 宏 |
| 有明确类型的只读数值 | `const` 对象 |
| 一组相关整数常量 | `enum` |
| 需要参数计算且类型固定 | 函数 |
| 复杂或多步骤逻辑 | 函数 |

现代 C 程序通常会限制宏的使用范围，仅在它确实具有预处理优势时采用。

## 二十三、与相关知识的联系

- C11 运算符：宏展开结果仍按照 C 运算符优先级和结合性计算。
- C12 表达式：宏参数可能是复杂表达式，也可能包含副作用。
- C22 函数定义与调用：普通函数通常比函数式宏具有更可靠的参数规则。
- C37 枚举：相关整数常量可用枚举表达。
- C39 预处理指令：宏由预处理器定义、展开和取消。
- C43 错误与调试：宏展开、文件位置和断言都与调试密切相关。

## 分层练习

1. 定义对象式宏 `MAX_STUDENTS` 和 `APP_NAME`，分别用于数组长度和程序标题。
2. 定义带完整括号的 `CUBE(x)`，测试 `CUBE(2 + 1)` 和 `100 / CUBE(2)`。
3. 手工展开 `MAX(a, b)`，解释为什么 `MAX(i++, j++)` 不安全。
4. 使用字符串化宏同时输出整数表达式的文本和值。
5. 分别使用宏、`const`、枚举和函数实现适合它们的功能，并说明选择理由。

## 小结

宏是预处理阶段的替换机制，不是普通变量或函数。安全使用函数式宏需要同时保护参数和整体表达式，并避免带副作用的实参。实际设计中，应优先选择类型明确、求值规则稳定的 `const`、枚举或函数，只把宏用于条件编译、位置记录和确有必要的代码模式。
